# 通用多传感监测管理系统 · 需求分析与开发指引（客户交付版）

> **版本状态：v1.0 · 已确认为开发基线**。本稿已替代 v0.1~v0.6 各历史稿（旧稿统一归档于 `归档\`），后续二人开发、接口/原型/验收均以此为准。改动请走版本修订，别直接覆盖本文。

> 定位：本稿是**给开发团队看的方向性需求分析**，不是说明书、也不是调研评审。它回答“给客户的系统**做哪些、先做哪些、边界在哪、数据结构长啥样、接口怎么定、哪些还没定**”。
> 前提：系统**最终交付给客户使用**。因此以下范围是**要做的产品定义**，不是“候选/待确认”。只有与客户真实现场强绑定、拿不到就做不了的项，才留在“待确认”。
> 依据：以最新调研（通用多传感监测管理系统）+ 老师近期口径为准。清远电厂架构书、参考视频、华测平台等只是案例，用于对标界面与功能，不锁定技术栈。

---

## 1. 产品一句话

给客户做一套**监测管理系统**：把现场传感器（首批=公司毫米波点形变雷达）报上来的数据统一收进来，在 **3D 数字孪生大屏**上把监测点标出来、看实时/历史曲线、超限自动告警、处理可追溯；**换场景、加传感器不改主框架**。

落地项目：清远电厂“天地一体化”监测预警系统；首批真实场景=灰库/库区边坡点形变监测。

---

## 2. 价值（给客户讲清楚）

| 客户的痛 | 系统解决 |
|---|---|
| 人工巡检贵、非 24 小时、发现晚 | 自动盯，24 小时不断 | 
| 出了事才补救 | 提前预警 |
| 数据散、看不清全貌 | 3D 一张图看所有点位 |
| 告警是否有人处理、怎么处理无记录 | 处理全留痕，可追责 |

一句话：**事前预警、避免事故、可追溯、支撑决策。**

---

## 3. 用户与角色

| 角色 | 核心任务 | 权限 |
|---|---|---|
| 领导/访客 | 看总体态势、趋势、大屏 | 只读 |
| 值班员 | 盯实时、收到告警、点确认 | 查看 + 确认 |
| 研判员 | 看曲线/照片/现场，判断真假 | 研判、建议升级/解除 |
| 运维员 | 处理设备掉线/没电/数据异常 | 设备、工单、维护记录 |
| 项目管理员 | 建项目/点位、配点数、配阈值 | 项目内配置 |
| 系统管理员 | 管账号/角色/权限/系统参数 | 系统配置 + 审计 |
| 设备/网关 | 上报数据、接指令 | 独立认证，仅数据链路 |

> 权限要点：RBAC + **项目数据范围隔离**（没授权看不到别的项目）；关键配置改动留审计。

---

## 4. 产品范围（已定，客户交付口径）

### V1 做这些
- **数据接入**：毫米波点形变雷达（唯一真实数据源）；预留其他传感器接入位。
- **3D 数字孪生大屏（必须）**：真实地形 + 监测点标注 + 左右面板 + 底部页签，效果对齐参考样图。
- **无人机影像**：航拍照片/视频接入，挂到监测点，3D 里看现场（不做飞控/自动建模）。
- **监测点闭环**：雷达数据 → 标点入 3D → 实时/历史曲线 → 超限告警 → 确认/研判/处置/解除 → 留痕。
- **设备运维**：掉线、没电、数据中断/异常识别、提醒、处理记录。
- **系统管理**：账号/角色/权限、点位/报警值/参数配置、审计、按日/周/月/年报表。
- **报警联动加密采集**：只预留接口/字段，暂不做真实联动。

### V1 不做（留到后续）
- 水位计、位移计、GNSS、测斜等其他传感器（先只雷达）。
- 相机视觉识别、无人机自动建模、多期三维变化检测。
- 多租户 SaaS、移动端、机器学习趋势预测、复杂微服务/大规模集群。

### 产品是“可扩展的通用平台”
通用性体现在**数据模型、数据接口、模块边界可扩展**；V1 只落地雷达这一个数据源，但架构预留加传感器/加场景。

---

## 5. 页面形态（三类，V1 先做前两个）

1. **运行管理工作台**：建档、设备/点位管理、告警处理、运维、权限、审计、报表查询。给内部值班/运维/管理员用，功能重、信息密。
2. **3D 综合态势驾驶舱（“壳子”，V1 门面）**：中央真实 3D 地形/正射 + 监测点标注（点 + 标签，按状态变色，可点开详情）；左侧点位列表、形变数据、历史时段；底部导航页签；深色科技风 + 泛光/水面/昼夜“科技感”。给领导/值班看全局，**外壳效果对齐老师给的两篇参考（Cesium 数字孪生大屏 / TvT.js 案例）**。壳子能力建议具备：真实地形/3D Tiles/倾斜摄影流式加载、**内置时间轴 + 动态实体**（雷达扫描、无人机航线、变形随时间变化）、风险/形变热力图、可视域/测距等空间分析（按需）。
3. **位移监测分析页**：单点/多点详情，X/Y/Z 累计位移、合位移、速率、趋势曲线，时间范围/粒度切换，多源叠加。研判用。

> 3D 驾驶舱是 V1 门面；若某场景不需要真实地理坐标/模型，可退化为二维地图或纯列表，但 V1 默认按 3D 态势图做。

## 6. 领域数据模型（骨架）

```text
项目 Project ──< 场景/区域 Scene ──< 监测对象 Object ──< 监测点 Point ──< 测项 Metric
   │                    │                     │                    │
   │                    │                     │                    └──< 测量值 Measurement(时序)
   │                    │                     │                        (value, unit, time, quality, raw_ref)
   ├──< 设备 Device ──< 绑定 Binding ──> 监测点
   ├──< 标定标定 Calibration(坐标系/参数/版本/有效期)
   ├──< 告警规则 AlarmRule(指标/窗口/阈值/等级/恢复/频控联动位)
   └──< 告警事件 AlarmEvent ──< 处置动作 AlarmAction(确认/研判/派发/升级/降级/解除)
   ├──< 运维记录 Maintenance / 巡查 Inspection / 媒体 Media(照片/影像/报表/成果)
```

要点：
- **设备—测点—测项解耦**：设备(物理) 与 测点(业务位置) 分开；一个测点可绑多设备，一个设备可有多个测项。
- **时序**：测量值按“项目/设备/测点/指标 + 时间 + 值/单位/质量标记/原始引用”存，不塞进无约束 JSON。
- **空间**：标准位置字段；确认有空间查询时启用 PostGIS；雷达目标坐标=站点经纬度 + 方位角 + 目标(角,距)。
- **告警分级 / 等级** 与 **处理状态** 是两个字段，不要混成一个（“红色+处置中”是合法组合）。
- **点形变≠面形变**：雷达是单点累计形变 + 地图标点；若接面状形变雷达，另设“成果清单”模型（时相/栅格/点云/瓦片/色带/兴趣区），不与单点曲线混存。

## 7. 数据接入契约

**标准单点消息**（雷达/传感器通用）：
```json
{
  "schemaVersion": "1.0",
  "messageId": "unique-id",
  "deviceId": "radar-001",
  "metricCode": "cumulative_deformation",
  "collectTime": "2026-09-09T10:00:00+08:00",
  "receiveTime": "2026-09-09T10:00:01.2+08:00",
  "sequence": 12345,
  "value": 2.36,
  "unit": "mm",
  "quality": "RAW",
  "attributes": { "signal": 0.91, "state": "normal", "angleDeg": 15.2, "distanceM": 87.4 }
}
```

约定：采集/接收时间分开；字段版本化；数值与单位分开；设备唯一标识不靠展示名；原始报文可追溯；同一（设备+消息ID/序号+采集时间）幂等去重；协议适配器只转标准消息，不写业务表。

**面状形变成果清单**（仅当接入面状雷达时启用）：resultSetId / projectId / deviceId / collectTime / resultType / coordinateReference / unit / bounds / storageObject(键) / checksum / quality / algorithmVersion；坐标系、分辨率、无效值、单位、算法版本随成果保存，兴趣点只引用不篡改成果。

---

## 8. 两条闭环（V1 必须跑通）

**A. 监测预警闭环**：设备上报 → 校验 → 入库 → 指标计算 → 规则触发 → 人工确认 → 研判 → 处置 → 解除 → 全程留痕。

**B. 运维/质量闭环**：设备或数据质量异常 → 告警 → 运维处理 → 恢复确认 → 维护记录。

> 系统不能停在“弹告警”。没有确认→处置→解除，就只是“报警器”，不是“预警管理系统”。

## 9. 开发优先级（V1 里程碑）

| 阶段 | 目标 | 关键点 |
|---|---|---|
| P0-A | 3D 大屏骨架能跑 | 免费地形/卫星 + 监测点标点 + 左右面板 + 底部页签；效果对齐参考 |
| P0-B | 雷达数据链路 | 模拟/真实雷达 → 标准消息 → 落库 → 曲线 → 告警 |
| P0-C | 管理后台闭环 | 登录/权限/Ui + 设备/点位建档 + 告警确认→处置→解除留痕 |
| P0-D | 无人机影像挂点 | 照片/影像上传 → 关联监测点 → 3D 里看现场 |
| P1 | 扩展 | 更多传感器、多场景适配、联动加密采集真实化、报表增强 |

> P0-A~D 跑通即“客户可演示初版”。先 A 后 B/C，因为 3D 是门面、也是验收重点。

## 10. 真正“拿不到就做不了”的待确认项（与客户/现场强绑定）

1. 首批真实设备与协议：雷达输出的是原始帧、解算结果还是两者都要？有没有样例数据？（决定接入方式与验收）
2. 项目区数据：有没有现成地形、正射影像、倾斜摄影、BIM/点云？还是先用免费卫星+地形顶一版？（决定 3D 真实度）
3. 无人机影像：只要照片/视频挂点，还是要按 EXIF/航点自动定位？（决定影像数据模型）
4. 告警阈值与处置流程：谁定阈值、几级、什么颜色、谁有权限升级/解除？报警联动加密采集的真实规则？（决定规则引擎）
5. 坐标系统与部署：用 CGCS2000/WGS84/地方坐标？部署在厂内网/公司/云？地图能不能联网？（决定空间模型与部署）
6. 界面对齐口径：华测 PS-SAR2000 是对齐“信息结构+交互”，还是也要接近其深色科技视觉？（决定 UI 规范）

> 除以上 6 项外（它们需要客户/真实数据才能定），本稿其余范围**按已定内容推进开发**，不再用“候选/待确认”稀释。

---

## 11. 验收（可核查，不写“做完页面”）

1. 3D 大屏“壳子”能跑：真实地形/正射 + 监测点“点+标签”标点、按状态变色、可点开详情；左右面板 + 底部页签；深色科技风 + 泛光/水面；**具备时间轴动态实体（如雷达/无人机/变形随时间）与风险/形变热力图**；整体观感对齐两篇参考。
2. 雷达（真实或同协议模拟）连续上报 → 识别设备 → 落库 → 3D 标点 → 曲线刷新。
3. 同一条消息重复发，不产生重复测量值/重复告警（幂等）。
4. 超阈值自动告警；持续超限不刷屏；等级升高能升级；确认—研判—处置—解除可全程追溯。
5. 数据延迟/缺失/断联，能标记质量问题并生成对应设备/数据告警。
6. 点一个监测点：最新值、历史曲线、照片/影像、告警全出来。
7. 未授权用户看不到别的项目；关键配置改动有审计。
8. 服务重启数据不丢；备份恢复后能查历史/告警/附件。
9. 新增一种传感器/换一个协议适配器，不改项目、告警、前端核心模型。

---

## 12. 技术方向（只定方向，细选后置）

- **B/S 前后端分离 + 模块化单体业务后端 + 独立边缘/协议适配层**；容器化部署（初版本地 Docker Compose）。
- 前端候选 Vue3（团队熟悉优先）；图表 ECharts；地图/大屏：**主引擎 CesiumJS**（真实经纬度/地形/3D Tiles/倾斜摄影/时间轴/空间分析，能做“监测点标真实地图、华测对齐”），**TvT.js(three-vue-tres) 作为 Vue3 数字孪生工程底座与案例墙参考**（12 个行业案例可直接 clone 改造，含无人机组航线、海洋船运航线、地图空间编辑器，并带国产化/信创适配）；普通管理页不需要地图就不引入。
- **壳子（3D 大屏）按参考效果实现**：Cesium `new Viewer + entities.add({position,point,label})` 做监测点标点；用 Clock/CZML 做时间轴动态实体；用 3D Tiles/倾斜摄影保证大场景丝滑；用后处理/场景特效做泛光、水面、昼夜。TvT.js 若用于非地理场景或工业孪生/信创，需 Node >= 20.18、Vue3 工程，且不适合离线桌面端。
- 后端候选 Spring Boot 3 + PostgreSQL（确认有空间需求启用 PostGIS）；时序库（小规模先 PostgreSQL 分区，规模上来再验证 TDengine）。
- 雷达解算/空间成果处理独立于业务后端（Python 进程），业务后端只管业务事实与状态，二者走版本化接口，不共享库表。
- 协议接入在真实链路确定后再选 MQTT/HTTP；**不锁 Kafka/Redis/K8s**，按规模与可靠性条件再启用。

> 技术选型不因案例（华测/说明书）而定；只按本项目真实设备、数据规模、团队与运维条件确定。

---

> **写在前面给开发的结论**：V1 = 华测式“管理后台 + 3D 态势驾驶舱 + 位移分析页”客户系统；真实数据源=毫米波点形变雷达；**先做 3D 大屏和雷达闭环**，无人机影像挂点，联动采集只留接口；通用性靠数据模型/接口/模块边界，不靠首版铺满所有设备。只剩 §10 的 6 项需要客户/真实数据确认，其余按本稿推进。
