# 通用多传感监测管理系统 · 需求说明（初版对齐版）

> 用途：给老师、项目的人看，用大白话讲清楚“这套系统是干嘛的、给谁用、初版做哪些、后面怎么扩展”。
> 依据：本稿以**最新调研文档**为主线（通用多传感监测管理系统，落点=清远电厂“天地一体化”，第一批真接=毫米波点形变雷达）。《清远电厂软件系统框架搭建说明书》**仅是技术参考**，不是主线，本稿不拿它当硬性要求。
> 本稿已按**老师 / 负责人近期口径**更新：先做一个**初版**、先做**好实现的场景**、初版**只接雷达**、航拍照片会有、3D 先用**免费/开源**、初版**本地运行**、最终**向华测对齐**。

---

## 一、这套系统是干嘛的（一句话）

公司做雷达和各种传感器，装在铁路、边坡、矿山、电厂这些地方，盯着**变形、位移、水位、结构安全**。

这套系统把这些设备报上来的数据**统一收进来**，在电脑网页上看：地图上每个监测点在哪、数值多少、有没有超限、要不要报警、报警了有没有人处理。而且要做**通用**——换地方、加传感器不用重做一遍。

- 第一个落地项目：**清远电厂“天地一体化”监测预警系统**。
- 初版真实接入：**公司的毫米波点形变雷达**（先只做雷达，别的传感器后面再说）。

---

## 二、为什么需要它（痛点 + 价值）

| 现在的问题 | 这套系统带来什么 |
|---|---|
| 靠人工巡检：贵、做不到 24 小时、发现晚 | 自动盯着，24 小时不间断 |
| 出了事才发现，损失大 | 提前预警，防患于未然 |
| 数据分散，不知道每个点现在啥状态 | 一张图/一个界面看全部 |
| 报警有没有人处理、怎么处理的，没留痕 | 处理过程全程记录，追得回来 |

价值一句话：**事前预警、避免事故、省钱、支撑决策。**

---

## 三、谁来用（角色）

| 角色 | 关心什么 | 能做什么 |
|---|---|---|
| 领导 / 访客 | 总体情况、趋势、大屏 | 只能看，不能改 |
| 值班监测员 | 实时数据、有没有报警 | 看实时、确认警情 |
| 专业研判员 | 曲线、照片、报表、现场 | 判断真假、建议升级/解除 |
| 运维人员 | 设备掉线、没电、数据异常 | 处理设备、做维护记录 |
| 项目管理员 | 某个项目/区域的配置 | 建点位、配点数、配报警值 |
| 系统管理员 | 账号、权限、系统设置 | 管人、管权限、管系统 |
| 设备 / 现场盒子 | 上报数据、接收下调指令 | 自动上传、偶尔听平台指挥 |

> **没授权的人看不到没被授权的项目**；改关键配置要留痕。

## 四、系统要做哪些事（功能）

### 1. 把数据接进来
- 雷达数据（初版核心）。
- 无人机航拍照片、现场照片。
- 人工报表（导入的和自动监测放一起看）。

### 2. 把东西管起来
- 项目、区域、监测点、设备（型号/编号/装哪儿/什么协议）。
- 每个设备怎么装的、装多久了、标定过没有、现在好坏。

### 3. 标到地图上（重点）
- 每个监测点在地图上算出位置，标出来。
- **点一个点**，能看到最新值、历史曲线、照片、报警。

### 4. 看数据
- 实时曲线 + 历史曲线（累计变形、变形速率）。
- 按项目/区域/点位/时间查，能导出成表格。

### 5. 预警 + 处理（重点）
- 超阈值 → 自动弹报警。
- **一个点超了，可自动让相关传感器加密采集 / 多报几次**（特色，先作为能力预留）。
- 确认 → 研判 → 处置 → 解除，每步留记录；不重复刷屏，级别高能升级。

### 6. 设备运维
- 掉线、没电、数据中断/异常 → 能发现、提醒、记录处理。

### 7. 系统管理
- 账号、角色、权限；点位/报警值/参数配置；改了什么留痕（审计）；按天/周/月/年出报表。

### 8. 扩展（以后）
- 加新传感器、加铁路/矿山/其他电厂，不改主框架就能接。

## 五、适用场景（为什么“通用”）

| 场景 | 坐标怎么描述 | 形态 |
|---|---|---|
| 铁路 | 里程 / 桩号 + 轨道 | 雷达、相机装轨旁或车上 |
| 边坡 / 矿山 | 平面坐标 + 高程 | 固定 / 车载 / 便携 |
| 电厂（清远） | 平面坐标 + 高程 | 雷达 + 传统传感器 + 无人机 |

不同地方坐标不一样，系统要能在不同坐标之间切换，各配各的标定，不改主程序。

---

## 六、这套系统的“不一样”在哪（差异化 + 难点）

1. **坐标 / 标定可切换**——换地方照样用（最关键、最花时间）。
2. **多传感器统一模型**——雷达/水位/GNSS/照片先统一成“设备 → 监测点 → 时序 → 告警”，前端一套逻辑。
3. **3D/地图点开一个点就看全**——最新值 + 曲线 + 照片 + 报警。
4. **无人机照片挂点**——点开能看这个点的履历。
5. **超限自动联动加密采集**——一个点超了，带动相关传感器多采。

> ⚠️ 能力边界：公司雷达是**点形变**（测**单个点**的累计变形 + 地图标一个点），**不是**整片云图/热力图（那是 GB-InSAR）。要跟甲方讲明白，别误会。

---

## 七、初版做到什么程度（已确认的口径）

**按老师口径：先做一个能跑的“初版”。**

### 初版范围
- **只接雷达**（毫米波点形变雷达）——这是初版唯一真实数据源。
- 场景先做**好实现的**（具体选铁路还是边坡，再定；先挑好上手的）。
- 把**“雷达数据接入 → 地图/3D 标点 → 实时/历史曲线 → 超限报警 → 处理留痕”**这条闭环先跑通。
- 无人机**航拍照片会有**，初版先做到“照片能传上来、挂到点位、点开能看”。
- 3D / 地图初版用**免费 / 开源**的（老师给了两个可仿照项目，见 §12）。
- 初版**本地运行**（本机跑起来能演示就行，暂不考虑上云/上线）。

### 初版先不做（以后再加）
- 水位计、位移计、GNSS、测斜等其他传感器（先只雷达）。
- 相机视觉识别、无人机自动建模/多期变化对比。
- 多租户、移动端、机器学习趋势预测、行业标准对接。

## 八、初版成功长什么样（验收）

1. 雷达能连续上报，平台能识别设备、落库、在地图/3D 上标出监测点。
2. 点一个监测点：看到最新值、累计变形 + 速率曲线、照片。
3. 超过阈值自动报警，报警不重复刷屏，能确认—研判—处置—解除，全程留痕。
4. 换一个场景（比如从电厂切到边坡），坐标标定能配得上，不改主框架。
5. 初版本地就能跑起来，给老师演示“点开一个点看全”的闭环。

## 九、风险：要趁早想清楚

| 风险 | 影响 | 怎么避免 |
|---|---|---|
| **坐标/标定能不能做通用** | 决定成败、最花时间 | 先拿一个易实现场景跑通标定，再抽成通用 |
| **范围越做越大** | 烂尾 | 初版只做“雷达闭环”，别的先后置 |
| **没拿到公司其他传感器协议/样例** | 接入层空转 | 初版只接雷达，别的预留 |
| **没有真实数据** | 验证、标定悬 | 先用模拟数据 + 找公司要雷达样例 |
| **需求还没定死** | 反复返工 | 这份文档当基线，改场景/加传感成本低 |

## 十二、参考：初版可仿照的对象（老师提供的）

> 只是“参考怎么搭”，不是需求；技术选型后面再定。

- **仿照 1：TvT.js（three-vue-tres）**——国产化 Web 3D 数字孪生底座，Apache-2.0 开源，自带 12 个行业案例，其中一个“地图空间编辑器（投影地图 + 倾斜摄影 3D）”比较贴合，适合做 3D 场景/大屏。
- **仿照 2：CesiumJS**——真正的 GIS/地理空间 3D 引擎，能处理真实经纬度坐标、地形、倾斜摄影、3D Tiles、时序轨迹动画、空间分析；**做“监测点标到真实地图上”的系统更贴合**。
- **最终对齐：华测（Huace）** 一类的专业监测平台。华测是测绘/监测起家，本质是地理空间 + 传感器监测平台，所以我们初版**坐标/地图/标点**这块要向它看齐，3D 可视化是“加分项”不是“核心”。
