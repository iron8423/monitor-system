# 工作日志 2026-09-18 · A（3D 大屏：离线真实地形资产）

> 需求（用户原话）：「图中的地形，通过卫星图片还原出来；雷达及其数据暂时使用模拟的。」
> 补充定案：「先做离线的」——运行期不请求任何在线服务，后续再接无人机航测数据。

## 一、先回答「卫星图片能不能建模」

结论与边界（9 条，详见 `docs/3D数字孪生_离线真实地形资产_20260918.md`）：

1. 单张卫星影像只有**颜色**没有**几何**：地形起伏必须来自 DEM、立体像对或无人机航测；
   影像能提供的是正射纹理。这两件事在方案里必须分开写，否则会被读成「拿张图就能生成 3D」。
2. 三条现实路线：① DEM + 正射影像贴图（本轮采用）；② 立体像对摄影测量（真重建，但
   300m 级场地性价比远低于无人机航测）；③ Google Photorealistic 3D Tiles（现成三维，
   但中国覆盖稀疏、必须联网、条款禁止离线缓存与再分发）。
3. **Google / Esri 影像不能离线下发**：两家的服务条款都禁止抓取、长期缓存与二次分发；
   Google 中国区影像还带 GCJ-02 偏移，和 WGS-84 测点叠加会整体错位。
   可离线且合法的免费高分辨率影像选择只有 Sentinel-2（10m，CC BY 4.0）。

## 二、选址：原演示坐标是平地

先下了清远周边约 12×15km 的公开地形瓦片做扫描，结果是：

- 原演示坐标 `113.0508E, 23.7208N` 的真实高程只有 **2–20m**——是平地，做不出边坡；
- 在市区以北约 4km 找到一处完整坡面：320×240m 内真实起伏约 96m、平均坡度约 15°，
  影像上有林地与一条浅色裸露带（山区道路/冲沟），适合讲「山脊 + 滑坡体」。

**这条不是「顺手换个坐标」**：测点与雷达的经纬度/高程、雷达朝向、7 条标定关系
全部要按新高程场重算，否则立柱会悬空、雷达会指着地形背面。

## 五、边界与后续

1. 30m DEM + 10m 影像 + 程序化细节只解决**观感**，不是测绘成果；

   它服务的是独立测试项目 900，如要换地形需另行重采样。

## 六、当日二次迭代（V2）：雷达"飞上天"、场景放大、点位重排

用户看大屏后报了两件事：**雷达浮在半空**；**场景太小、地形看不出关系**，
希望用更多卫星/高程数据、把场景做大、雷达与测点位置放得更合理。

### 1. 雷达为什么会在天上（bug 复盘）

`build_radars()` 写雷达 `localPosition[2]` 时填的是**绝对高程**（基准面 + 相对高度），
生成迁移草稿时又加了一次基准面，于是 `device.altitude` 被算成「基准面 ×2 + 相对高度」，
两台雷达整体抬高 107m。ENU 本地坐标的 +Z 零点就是基准面，这里只能写相对高度。

修法：`localPosition[2]` 回归相对高度，绝对高程另存 `absoluteAltitude`；迁移 **V19** 重写
两台雷达的 `altitude`。另外顺带修了解算朝向时的**圆均值陷阱**——目标跨 0° 时圆均值被
密集一侧拉偏（南侧雷达实际 52.1° 弧被算成偏差 32.8°，误判超出 ±30° 视场），
现改用「最小覆盖弧中点」。这两个都是"数值看着正常、画面一看就不对"的典型，
教训是：**单位口径要写进字段名，且在浏览器里实拍验证**。

### 2. 场景与点位（V19）

- 场景 320×240m → **1000×750m**；真实起伏 96m → **237m**；网格 2m→4m（94,000 面）；
  纹理 2048×1536 → **4096×3072**；数据源 2+4 张瓦片 → **4+9 张**；GLB 1.00 → 2.74 MiB。
- 两台雷达移到**监测区之外的稳定地面**：北侧 (150,300) 台地、南侧 (100,−300) 坡脚谷地，
  量程 265m → 620m；7 个测点按「山脊 3 点 + 滑坡体 4 点」重排到整片坡面，
  每台雷达的目标方位跨度 49.8° / 52.1°（±30° 视场内），最小净空 1.15m / 1.58m。
- 实拍确认：雷达杆、扇面、7 个测点全部落在坡面上（截图
  `docs/samples/screen-qingyuan-hillside-v2-20260918.jpg`）。

### 3. 数据源的天花板（写在案）

免费可离线的上限是「30m 高程 + 10m 影像」；再精细只能买授权影像或等无人机航测。
Google/Esri 的瓦片禁止离线缓存与再分发，不能拿来做内网交付。

## 七、当日三次迭代（V20）：多场景（桥梁 / 铁路 / 工厂）+ 模拟数据

用户问了三件事：公开 DEM 有没有 5m、纹理为什么"什么都没有"、能不能加多个场景
（野外桥梁 / 铁路 / 郊外工厂）并各自带模拟形变数据。逐条回答与落地：

### 1. DEM：公开数据基本只有 30m

SRTM / ASTER / ALOS AW3D30 / Copernicus GLO-30 / NASADEM / FABDEM 全是 30m 档；
1–2m 的（USGS 3DEP、英国 EA、荷兰 AHN、瑞士 ALTI3D）都只在各自国家；
5m 与更高只有商业采购（AW3D 5m、WorldDEM、国内高分/资源三号测绘产品）或无人机航测。
**本资产用的是 SRTM 派生 30m**（terrarium 瓦片 z=15 过采样）。影像同理，免费可离线的
只有 Sentinel-2 的 10m；"纹理什么都没有"的根因就在这里——1000m 场景里它只有约 100 个
真实像元，放大到 4096 宽全是插值。补的是程序化细节，不是分辨率。

### 2. 多场景按「项目」组织，前端零改动

一个项目 = 一处场址 = 一份数字孪生资产 = 自己的一批测点/设备/标定；大屏顶栏的项目下拉
就是场景切换。三个新场景各 6 个测点 + 1 台雷达（420–620m），标定由生成器按视线解算：

| 场景 | 资产 | 结构体 | 截图 |
|---|---|---|---|
| 野外桥梁 | `qingyuan-bridge-1.0.0` | 桥面/桥墩/桥台/护栏/灯柱 | `docs/samples/screen-scene-bridge-20260918.jpg` |
| 山区铁路 | `qingyuan-railway-1.0.0` | 路基/道砟/钢轨/轨枕/接触网支柱 | `docs/samples/screen-scene-railway-20260918.jpg` |
| 郊外工厂 | `qingyuan-factory-1.0.0` | 地坪/厂房/储罐/烟囱/围墙 | `docs/samples/screen-scene-factory-20260918.jpg` |

结构体是**程序化建模**的示意级几何（`tools/terrain_asset/features.py`），与地形拼在
同一个 GLB 的第二个 primitive 里（顶点着色 + unlit），所以仍然是一份资产、离线、可复现。

### 3. 模拟数据：一条命令灌四个场景

`tools/radar_simulator/seed_all_scenes.sh`：每个场景 12 小时历史（BACKFILL，喂曲线）+
当前实时值（REALTIME，喂 `latest`），四场景合计约 1500 行，实测 0 拒收。

### 4. 顺带修掉的两个"静默"缺陷

- **结构体在浏览器里根本不显示**：GLB 里结构体的 bufferView 索引写错了一位
  （指向了纹理那条），地形照常渲染、只有结构体消失——只看画面很容易误判成"模型没做"。
  已修（`write_glb` 的 5..8）。
- **严格契约下整批被拒、界面却一切正常**：`radar_simulator.py` 的位置表是 V11 时代手抄的，
  V18/V19/V20 改标定后它全部过期，报文因 `POSITION_CALIBRATION_MISMATCH` 被整批拒收。
  现在位置与设备映射由 `emit_scene_migration.py` 从 coverage.json **同源生成**
  （`tools/radar_simulator/scene_positions.json`），不再有第二份手抄值。
