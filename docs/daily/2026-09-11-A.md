## 二、两个后端缺陷（真机验证时撞出来的，与选哪版前端无关）

### 55. 缺陷一：`/devices` 与 `/projects/{id}/summary` 对同一台设备给出相反结论

**现象**（浏览器实测）：设备页显示 radar-001 **在线**（最后上报 `2026-09-10T16:37`，已过 18 小时），
同一时刻总览 KPI「在线设备」显示 **0**。两个数都是后端给的。

**根因**：`device.status` 这一列的语义是**人工显式标注**（只有 `FAULT` 有意义，
在线/离线由 `lastReportTime` 推导，见 `DeviceStatusPolicy#statusOf`），但 V2 种子里写进去的是 `ONLINE`。
而 `BaseCrudController` 的通用列表**直接吐实体**，于是列表返回存量值、永久不变；
`/devices/{id}/status` 与项目概览的在线设备数则都按策略**现算**。

**为什么必须修在后端**：前端无法调和——要么把 5 分钟判据在浏览器里抄一遍（判据就此分叉，
而告警是按后端判据发的），要么按设备数逐个去调 `/{id}/status`（N+1）。
`DeviceView.vue` 的注释里明确拒绝前者，那是对的，所以修在列表端点。

**修法**：`DeviceController` 覆盖基类的 `list()` 与 `get()`，返回前把 `status` 换成
`DeviceStatusPolicy.statusOf(d)`（只改返回对象，**不回写**——这是读时推导，不是把推导结果持久化）。
`statusOf` 对 `FAULT` 是幂等的，所以显式标注不受影响。

**实测**（compose / postgres profile）：

| 端点 | 修前 | 修后 |
|---|---|---|
| `GET /devices`（列表 status） | `ONLINE`（存量值） | **`OFFLINE`**（现算） |
| `GET /devices/1`（详情） | `ONLINE` | **`OFFLINE`** |
| `GET /devices/1/status` | `OFFLINE` | `OFFLINE`（对照，未变） |
| `GET /projects/1/summary` → `onlineDeviceCount` | `0` | `0`（对照，未变） |

修后三者一致。灌入模拟器数据设备回到 ONLINE 后，列表/详情/状态/概览**同时**变成 ONLINE 与 1。

**回归**：验收套件 173/173 全过。已确认套件只对 `/devices/{id}/status` 与 `/devices/1` 的
`updatedAt` 断言，**未**断言列表里的 `status` 值，故本次收窄是安全的。

### 56. 缺陷二：验收链的第一环在 PG profile 上从未走过

**现象**：前端测点页列出 7 个种子测点，曲线却是空的——`GET /points/1/series` 返回 `points: []`。

**查库**：`measurement` 有 98 行，但 `point_id` 全是 1001–1017、`point_code` 全是
`P-ING-…/P-QRY-…/P-ALM-…` 这种**验收套件自建的一次性测点**；种子测点 `P-HK%` 的行数是 **0**。

**根因**：模拟器昨天灌的数据进了 H2（dev profile，内存库），随进程一起没了；
compose 跑的是 PG，库里只剩套件残留。`tools/acceptance/08-simulator.sh` 虽然补上了「模拟器」这一环，
但它跑在**空库 `--fresh`** 或临时测点上，**从没在 PG 的种子测点上跑过**。
也就是说：「模拟器 → 曲线出点」这条链在 dev 上验过，在部署形态（PG）上没验过。

**处置**：对 compose 后端跑一次模拟器，造一段覆盖 24 小时的历史曲线
（48 轮 × 30 分钟、`--backdate-days 1`），`accepted=672 / rejected=0 / duplicates=0`。

**实测结果**：`/points/1/series` 由 0 点变 **47 点**（`P-HK01`，`2026-09-10T11:25` → `2026-09-11T10:25`）；
总览 KPI 由「最大形变 —」变 **−1.2224mm**、「在线设备」0 → 1。

> 顺带澄清一个容易看错的地方：`maxDeformationMm` 是**带符号**的（`ProjectSummaryService#maxDeformation`
> 取各测点最新值中绝对值最大者，负向形变不取绝对值），所以它可以是负数。
> −1.2224 经逐点核对是对的（`P-BP02` 最新形变 −1.2224，绝对值最大）。
> 但卡片上「最大形变」配一个负数会让人以为算错了，故在标签旁加了一个问号提示说明口径。
