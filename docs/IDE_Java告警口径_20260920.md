# IDE 里的 Java 告警：口径、修了什么、怎么恢复分析

> 起因：2026-09-20 用户在 VS Code 的「问题」面板里看到 **41 条**（35 警告 + 6 提示），
> 问"还有多处警告"。本文把这 41 条按**性质**分成三类，说明每一类怎么处理、为什么这样处理。
>
> 先说结论：**这些都不是构建告警**。`./mvnw compile` 的 javac 输出是干净的（0 warning），
> 所以 CI 从来没看见过它们——它们只存在于 IDE 的语言服务器（Eclipse JDT）里。

## 3. 噪音：为什么关掉，而不是逐处加抑制

### 3.1 "Null type safety" 那 25 条是什么

典型长这样：

```
Null type safety: parameter 'this' provided via method descriptor
Function<Organization,Object>.apply(Organization) needs unchecked conversion
to conform to '@NonNull Organization'
```

来源是：Spring 6.2+ / Jackson 等库的 API 带了 JSpecify 注解（`@NonNull` 等），
而**本工程自己的类型没有注解**。JDT 在 `automatic` 模式下遇到"注解 API 与非注解代码混用"
就逐处提示"未检查的转换"。它既不说明哪里会空指针，也不给出改法——除非先把工程改成
全量 `@NullMarked`。

> 判断依据不是"看起来像噪音"：这 25 条**没有一条**是"值可能为 null"的类型警告，
> 全部是"注解体系不一致导致的转换提示"。与之对照，`SeriesWindowPolicy` 那条
> `Potential null pointer access` 是实打实的分析结论，我们改了代码而不是关分析。

### 3.2 那 6 条 "suppression not analysed" 是什么

代码里原本有 33 处 `@SuppressWarnings("null")`（32 个文件）——那是**更早一轮**为了让
问题面板安静而加的。但本工程从未启用 null 分析，于是：

* 抑制不生效（没有东西可抑制）；
* JDT 反过来提示「你抑制了一个没被分析的类别」→ 每个带注解的类多一条提示。

所以这一次把那 33 处**全部删掉**（`@SuppressWarnings("null")` 在 javac 下本来也什么都不做），
面板里那 6 条提示随之消失。

### 3.3 现在的设置

`.vscode/settings.json`（**已纳入仓库**，`!.vscode/settings.json` 例外规则在 `.gitignore` 里）：

```jsonc
{ "java.compile.nullAnalysis.mode": "disabled" }
```

这样每个人的面板口径一致，而不是"谁配过谁没有"。

## 4. 想把 null 分析真正用起来怎么办

顺序不能反（先注解体系、后开分析）：

1. 给每个包加 `package-info.java`：
   ```java
   @NullMarked
   package com.monitor.telemetry.service;
   import org.jspecify.annotations.NullMarked;
   ```
   （`org.jspecify:jspecify` 已随 Spring 6.2+ 进入依赖树，无需新增依赖；
   个别确实可空的位置用 `@Nullable` 标注。）
2. 把 `java.compile.nullAnalysis.mode` 改回 `automatic`。
3. **把这次删掉的抑制按需加回**——在注解体系下它们才会真的生效。

在此之前，把分析开着只会得到 25 条无法处理的提示，以及"真问题被淹掉"的日常。

---

## 5. 一句取舍

**关掉的是"注解体系不匹配"的提示，不是"能不能出空指针"这回事。**
后者靠三件事兜：`SeriesWindowPolicy` 这类能静态看出的一律改代码；
参数校验走 `@Valid` / 业务异常；数据面没有的地方在验收套件里断言（614 条）。
