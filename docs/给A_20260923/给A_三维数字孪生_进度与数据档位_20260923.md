## 1. 项目概述

### 1.1 做什么

把现场（电厂库区 / 边坡）的静态空间数据（地形、影像、构筑物）与动态监测数据（形变雷达的逐点数值）合成一个可在浏览器里操作的三维孪生体，实现：

**接入 → 展示（三维 + 曲线 + 面板）→ 告警 → 处置留痕** 的闭环，并可换场址、换数据源、换精度而**不改主框架**。

### 1.2 分层与分工

```
【数据源层】                    【孪生体层】                   【应用层】
雷达（形变量/速率/质量）─┐
公开 DEM / 卫星影像      ├─► 资产流水线 ─► 离线 GLB 资产 ─┐
航测成果（待获取）       │   （抓取/合成/校验/版本）        ├─► 三维大屏（Cesium）
图纸·CAD·BIM（待获取）───┘                                │   测点状态 / 弹窗 / 雷达视场
控制点（待获取）────► 配准与残差校核 ─────────────────────┤
                                                          │
雷达数据流 ──► ingest 契约（校验/幂等/拆行）──► 库 ────────┴─► 曲线 / 告警 / 处置 / 审计
```

### 1.3 现在的演示形态（为什么画面是苏黎世）

清远电厂的**真实空间数据一份都还没到位**（无图纸、无控制点、无航拍、无影像授权）。为了不停工，B 侧把整套流水线搬到**瑞士苏黎世 Werdhölzli 污水处理厂**周边做样板——那里有**全域免费且带真几何**的官方开放数据（swisstopo OGD），厂区形态（厂房、水池、管廊、住宅成片）最接近我们"电厂厂区"的监测场景。

> 注意两点，汇报时不要含混：① 演示锚点 8.506°E / 47.3935°N 是**苏黎世**，系统里清远那条记录仍是**模拟选址**；② 苏黎世那套资产是**样板**，不是交付成果。

|---|---|---|---|---|

### 2.3 Phase 0.5（2026-09-23 完成）：大屏观感与交互基线

这一轮处理的都是"现场演示会当场丢人的问题"，全部有实测数字：

| 事项 | 问题 | 做法 | 实测结果 |
|---|---|---|---|
| 测点标签挤成一坨 | 拉远时 7 个标签叠在一起、还压住分区名 | 屏幕空间避让（投影成 CSS 像素 → 按矩形贪心放置，竖直优先、必要时横向；分区名优先占位） | 四个机位**互压 0 对、与分区名交叉 0 对** |
| 标签被挪开看不出属于谁 | 标签上移两三百像素后失去对应关系 | 补**屏幕空间引线**（2D canvas 叠加层，不用 3D 折线——会被山体遮挡） | `requested/projected/drawn = 6/6/6` |
| 远景糊 | 靠近方框边缘时命中低层瓦片 | 远景金字塔补 **z16/z17** | 新增 207 张、失败 0；页面命中 z16 14 张 / z17 7 张 |
| 顶部一直红"加载失败" | 批量取最新值接口 **24 秒**，超过前端 15 秒超时 | 后端日志 `com.monitor: debug → info`（debug 会把每条 SQL 连参数一起写） | 当时降到 **4~21 ms**，红灯消失 |
| 相机能推到地下 | 回归脚本直接用 `zoomIn()` 绕过控制器限制 | 脚本改用真实滚轮事件 | 推进到**离地 424 m**、拉远 **1535 m** 均正常 |

**顺带修掉三个真 bug（都会毁演示）**：
1. `postRender` 里遇到 NaN 坐标抛异常 → Cesium 整帧渲染停止 → 大屏冻住（改为先验有限值 + 兜底跳过）；
2. 从实体读标签文字拿到的是 Property 对象，`String()` 得到 `[object Object]`，字宽算错导致避让漏判（改为 `getValue(time)`）；
3. 远景瓦片模板 `{z}/{x}_{y}.jpg` 与 Cesium 默认模板不一致会**全部 404**，而页面看着"还行"（其实在用兜底层渲染）——这类"假故障"已经写进交接文档的坑清单。

### 2.4 Phase 1A（2026-09-23 完成）：数据档位研究 + 航拍级参考档

**目的**：公司问"同时有航拍和卫星数据时，这套方案能做到什么样子，先给个尽量逼近上限的样子"。B 侧用公开数据做了三轮实验，**全部零采购**：

| 实验 | 场址 | 变量 | 结论 |
|---|---|---|---|
| **T1 vs T2** 数据等级对照 | 瑞士 Grande Dixence 大坝周边 | 30 m DEM + 10 m 影像 → **0.5 m DEM + 0.41 m 影像**（网格、纹理、机位完全相同） | 画面从"色块"变成"能读地形与构筑物"；纹理真实信息量 **3.6 倍** |
| **T3 厂区版** 真几何 | 苏黎世 Werdhölzli | 只有地形+影像 → **叠加官方 CityGML LoD2（523 栋真几何）** | "看得清 ≠ 有立体"：叠加后才有体积、遮挡与可量测性；13.84 MB / 192,753 面 |
| **航拍级参考档** | 同上 | 0.2 m 影像 + 4 m 网格 + 4096 纹理 + 白模 → **0.1 m 正射 + 2 m 网格 + 8192 纹理 + 屋面贴真实影像** | 同一场址"免费档能到哪"的直观答案（见 §3.3 与 §3.5） |

参考档做出的关键改动（都在 B 侧工具链里，不影响主框架）：

- `citygml_to_glb.py` 支持**屋面/墙面分流**：屋面贴正射影像（俯视就是真实地貌颜色），墙面走 PBR 受光；
- 屋面 UV 与正射影像**逐像素对齐**（把图元 UV 轮廓画回正射图核对过）；
- 关掉 AO 与实时阴影：AO 会在 2 m 网格 + 0.1 m 正射下自遮蔽出规则斜纹；正射影像里本来就有真实日照与投影，再叠实时阴影属于重复计算；
- 参考档与现状档**互不影响**：`npm run dev` 走现状档，`vite --mode hires` 走参考档（`.env.hires.local`）。

> **"模型飘在天上"这个 bug 就是高程基准问题的近亲**：演示资产按真实海拔（395 m）挂在椭球面（0 m）之上，于是整块地悬空 395 m、边缘是断崖。修法是让资产地面正好落在椭球面上（只对演示资产生效，别的项目不受影响）。**真数据进来时，同一类问题会以"整体偏移几米~十几米"的形式再出现一次**，所以高程基准必须在数据交接单里写死。

## 3. 数据源指标：全免费档 vs 付费（商用）档

### 3.1 先把三个"精度"分开，否则结论一定是错的

| 层 | 说的是什么 | 决定什么 | 现状 |
|---|---|---|---|
| **数据精度** | 源数据本身能分辨多小（GSD / DEM 格网 / 几何来源） | "像不像真的" | 免费档：0.1~10 m；付费档：0.03~0.5 m |
| **渲染精度** | 网格多密、纹理多细、材质怎么算 | 观感与性能 | 我们可控：网格 2~4 m、纹理 4096~8192 |
| **工程精度** | 能不能当尺寸或形变依据（残差、基准） | 能不能"用于工程判断" | **只能靠图纸/控制点/航测**，与渲染精度无关 |

**这三层目前是脱节的**：清远侧的渲染精度（2 m 网格 / 0.29 m 纹理）远高于数据精度（30 m DEM / 10 m 影像），看起来细，但**信息是"化妆"出来的**——红线里明确禁止把观感当测绘精度说。

### 3.2 全免费档：今天大屏上的东西就是它

#### （a）瑞士侧（演示场址，全部官方开放数据，零采购）

| 数据 | 来源 | 精度 / 规格 | 体积 | 许可 |

### 3.7 结论（可以直接抄进汇报）

1. **"同时有航拍和卫星数据能做到什么样"，现在有图有数了**：本文参考档 = 0.1 m 正射 + 0.5 m 高程 + 真几何建筑，是**公开免费数据的上限**。
2. **免费档能到 L1**：场址、道路、主要地物可辨认，测点位置合理；**清远侧的免费数据（30 m/10 m）连 L1 都勉强**。
3. **要到 L2（可用于工程判断）必须花钱或找甲方**：优先找甲方要**总平面图/CAD/BIM + 控制点 + 高程基准说明**（零成本，决定 L2 能不能达成）；其次才是影像采购与航测。
4. **技术侧没有阻塞**：换场址、换数据源、换精度都只换参数、不改代码——这一点已在瑞士公开数据上完整验证过。

## 7. 提交与交接方案（分支策略）

> 这一节是 09-23 傍晚定的口径，用来替代之前一直悬着的"提交策略未定"。

### 7.1 结论：开新分支是对的，但要补三件事

**"新建一个分支、把所有代码提交上去，A 完整拉下来跑，就不会互相覆盖"——这个思路可行，我同意用新分支**。理由：

- B 侧当前在 `feature/3d-visual-preview` 上**有 5 个提交是 A 没拉到的**（`origin/feature/3d-visual-preview` 停在 `6fe4726`，本地已到 `bbf24ff`），再加上工作区里 **831 项未提交改动**；
- 如果继续往同一个分支上堆，A 那边"我到底拿到哪一版"会一直说不清；**新建一个语义明确的分支 + 一个 tag，等于给这次交接拍了一张快照**。

但有三个点必须补上，否则 A 拉下来还是跑不出我们今天看到的那一屏：

| # | 问题 | 为什么会出问题 | 补法 |
|---|---|---|---|
| 1 | **本地演示依赖的 `.env.*.local` 全在 `.gitignore` 里**（`*.local` 被忽略） | A 拉下来没有 `VITE_ASSET_OVERRIDE`、`VITE_ANCHOR_OVERRIDE`，看到的是**清远电厂**那套资产（`.env.development` 的默认值），不是我们演示的苏黎世现状档 | 把演示档位做成**可入库的 mode 文件**（`.env.hires` / `.env.qingyuan`，并把 `.env.development` 默认值改成苏黎世现状档），见 §7.5 |
| 2 | **资产缺署名与来源说明**：`models/wh-plant/`、`wh-terrain/`、`dixence-t1|t2/` 目录里只有 GLB，没有 `ASSET_PROVENANCE.md` | swisstopo 是 **OGD（开放数据）**，**允许离线缓存与再分发，但要求署名**；缺了这份说明，仓库里就是"来源不明"的资产 | 每个资产目录补一份 `ASSET_PROVENANCE.md`（数据源 + 许可 + 生成脚本与参数 + SHA-256），参考档那份从 B 侧工作区拷入并**改掉里面陈旧的样板文字** |
| 3 | **`public/preview.json` 与具体资产绑定**（`groundHeightM` / `terrainSurfaceHeightM` 决定"整块地下移多少"） | 换资产不换这个文件 → 模型会悬空或埋进地面（"飘在天上"就是这一类问题） | 提交时按默认档放对数值；多档并存的问题列入待办（见 §7.9） |

另外，"切分支会不会覆盖 A 的东西"要说得更准确一点：**git 不会覆盖 A 已经提交的历史**；真正的风险是 A 工作树里**未提交的本地改动**，`git switch` 会拦着不让切、或者被带走。所以下面 §7.6 推荐 A 用 **`git worktree`（另开一个目录）**，从机制上把风险清零。
