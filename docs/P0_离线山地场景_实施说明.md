# 完全离线低多边形山地场景实施说明（V2）

## 已实现

- 320m × 240m 的程序化低多边形山体 GLB 升级为 38,400 个三角形、约 3.08MiB。
- 山体包含复合山脊、沟谷、滑坡后缘、滑坡槽、坡脚堆积体、道路和排水带，使用顶点色，不依赖纹理。
- Cesium 使用 ENU（东-北-上）局部坐标加载 GLB；两台雷达的平台、水平/垂直视场和目标 LOS 由实体绘制。
- 7 个原有监测点收拢到同一山体，点号保持 `P-HK01~03`、`P-BP01~04` 不变，
  影像目录无需改；模拟器会按北/南两台雷达的标定归属自动选择 `deviceId`。
- 默认 `VITE_SCENE_MODE=mountain`，运行时不请求 Cesium ion、在线地形或在线影像。
- V9 建立基础山地场景，V11 自动升级精细模型、两台雷达、点位高程及雷达目标标定。
- 原有 SSE 实时数据、告警着色、时间轴回放、热力圈和点击浮窗继续复用。

## 为什么没有直接搬用 three-vue-tres 的模型

当前系统的三维底座是 Cesium，而 three-vue-tres 的示例基于 Three.js/Tres；直接搬场景代码会引入第二套
渲染体系和生命周期。其公开仓库中也没有发现可以明确作为本项目离线山地资产直接交付的本地 GLB。
本次因此采用自有生成器，授权链和坐标链都更短，也便于以后按项目参数重新生成。

## 启动

Docker 形态：

```bash
cp .env.example .env
docker compose up -d --build
```

访问 `http://localhost/screen`。V9～V11 会由 Flyway 自动执行；已有数据库不需要清库。

开发形态：

```bash
cd backend
./mvnw spring-boot:run
```

另开终端：

```bash
cd frontend
npm install
npm run dev
```

访问 `http://localhost:5173/screen`。

“完全离线”指应用运行时的山体、Cesium 运行资源、底色和可视化均由本机提供。第一次安装 npm/Maven
依赖或拉取 Docker 基础镜像仍需网络或预先准备好的离线依赖缓存/镜像包。

## 重新生成模型

```bash
python3 tools/mountain_asset/generate_mountain_glb.py
```

生成器只使用 Python 标准库。若调整 `POINTS`、锚点或地形函数，应同时根据新生成的 `points.json`
新增下一版 Flyway 迁移；不要修改已经执行过的 V9～V11 校验和。

## 切回全球地图

在 `.env` 或 `frontend/.env.local` 中设置：

```bash
VITE_SCENE_MODE=globe
VITE_CESIUM_ION_TOKEN=<your-token>
VITE_TERRAIN_MODE=ion
```

Vite 环境变量是构建期注入的；Docker 形态修改后必须重新构建 frontend 镜像。

## 已执行校验

- `npm run build`：通过。
- GLB 二进制头、JSON/BIN chunk、长度、顶点数、包围盒：通过。
- `points.json`、`coverage.json` 与 V11 中 7 个标定目标逐项一致：通过。
- WGS84 点位反算到模型 ENU 的最大误差：约 0.0057m。
- 每个目标均在所属雷达量程、水平/垂直视场内且地形 LOS 净空为正：通过。
- `git diff --check` 与生成器 Python 语法检查：通过。

当前执行环境缺少后端 Maven 依赖缓存且无法访问 Maven Central，因此 `./mvnw test` 未能下载
Spring Boot 父 POM。交付机器网络可用或具备 Maven 缓存后，应再执行一次该命令。

## P0 边界

- 山体是演示几何，不是 DEM 或实景测绘成果。
- 雷达扇区表达覆盖方向与范围，不是电磁传播仿真。
- 热力圈仍是离散点示意，不做 IDW/Kriging 插值。
- 若下一阶段需要真实山形，建议保留当前 ENU/配置接口，只替换 GLB 和对应点位，不改实时数据链路。
