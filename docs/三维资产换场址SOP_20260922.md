# 三维资产换场址 SOP（2026-09-22）

> 目的：**换一个新场址（或换影像源、换精度），照着这份文档走一遍，就能产出一份能直接上大屏的离线三维资产。**
> 适用：新项目落地、换个地块演示、影像源升级、精度调整。
> 责任分工：B 侧执行 1~6 步；第 7 步（正式化）需要 A 侧配合；数据类前置条件（图纸、授权、控制点）由项目负责人向甲方要。

---

## 0. 先明确三件输入（缺一件就会返工）

| 输入 | 具体要什么 | 谁提供 |
|---|---|---|
| **场址位置与范围** | WGS-84 经纬度（建议 6 位小数）+ 东西×南北米数（含最远测点、雷达、外扩） | 项目负责人 / 甲方 |
| **精度目标** | 只要"演示像现场"，还是要"支撑形变结论" | 老板 / 甲方 |
| **授权口径** | 是否允许对外；影像是内部预览还是要交付 | 老板 / 甲方 |

⚠️ 若涉及采集测量级结论，还必须拿到**控制点坐标（3~6 个不共线点）**和**高程基准说明**（椭球高 or 1985 国家高程），否则"模型准不准"只能靠眼看。

## 1. 全流程一览

```
场址坐标/范围
   │
   ├─① 抓 DEM + 底图      tools/terrain_asset/fetch_sources.py     → sources/
   ├─② 抓中心高清影像      tools/imagery_fetch/fetch_imagery.py     → center-z19/
   ├─③ 建地形资产          tools/terrain_asset/build_terrain_asset.py → *.glb + 场景配置 + 迁移草稿
   ├─④ 合成纹理            tools/terrain_asset/composite_imagery.py → composite-8192.jpg
   ├─⑤ 换纹理 + 校验       tools/terrain_asset/replace_texture.py + validate_glb.py
   ├─⑥ 抓远景层（可选但推荐）tools/imagery_fetch/fetch_farfield.py   → frontend/public/farfield/
   └─⑦ 接入与正式化        预览用 .env.local 覆盖；正式走"新版本号迁移 + asset_sha256"
```

**总耗时参考**（清远电厂 6000×4500 m 实跑）：① 约 2 分钟 ② 约 6 分钟 ③ 约 40 秒 ④ 约 3 秒 ⑤ 约 2 秒 ⑥ 约 6 分钟。**主要时间花在抓瓦片。**

## 2. 逐步命令（以清远电厂 6000×4500 为例，可直接替换参数）

### ① 抓 DEM + 底图

```bash
python tools/terrain_asset/fetch_sources.py \
  --anchor-lon 113.541523 --anchor-lat 24.4162209 \
  --width 6000 --depth 4500 --margin 0 \
  --out work/<场址代号>/sources
```

- 产物：`sources/dem/15/*.png`（terrarium 高程）、`sources/imagery/16/*.jpg`、`manifest.json`（含每张瓦片 SHA-256）。
- 清远电厂实跑：DEM 30 张 + 哨兵影像 99 张。
- 重复执行不会重复下载（有缓存）。

### ② 抓中心高清影像

```bash
python tools/imagery_fetch/fetch_imagery.py --source google \
  --anchor-lon 113.541523 --anchor-lat 24.4162209 \
  --width 1000 --depth 750 --zoom 19 \
  --out work/<场址代号>/center-z19
```

- `--source` 可选：`google`（0.27 m/px，需代理）、`gaode`（0.55 m/px，直连，GCJ-02 已内置反算）、`bing`（该场址是建设期旧图，慎用）、`esri`、`eox`（10 m，合规可交付）、`tianditu`（需 key）。
- 产物：瓦片 + `stitched.png` + `stitched.pgw`（QGIS 可直接打开对位）+ `manifest.json`。
- 抓取慢或断流时**直接重跑同一条命令**：脚本会续抓（`--overwrite` 才重抓）。

### ③ 建地形资产

```bash
python tools/terrain_asset/build_terrain_asset.py \
  --scene mountain \
  --sources work/<场址代号>/sources \
  --width 6000 --depth 4500 \
  --cells-x 750 --cells-y 562 \
  --texture-width 4096 --texture-height 3072 \
  --asset-name <资产名> \
  --out work/<场址代号>/build
```

- `--scene` 预设：`mountain`（纯地形）/ `bridge` / `railway` / `factory`（带示意结构体）。
- **网格密度**：`cells-x/cells-y` 决定三角面数，经验值——
  | 场景尺寸 | 建议网格 | 三角面 | GLB 几何 |
  |---|---|---|---|
  | 400×300 m（桥梁） | 4 m | 约 1.5 万 | <1 MB |
  | 1000×750 m（边坡） | 4 m | 约 9.4 万 | 约 3 MB |
  | 3000×2250 m | 4 m | 约 84 万 | 约 24 MB |
  | 6000×4500 m | 8 m | 约 84 万 | 约 24 MB |
- `--material unlit`（默认，与历史资产一致）/ `--baked-shade 1.0`（阴影烘进纹理）。
- 产物：`<资产名>.glb`、`scene-config.json`、`scene-update.sql`（迁移草稿）、`coverage.json`、`ASSET_PROVENANCE.md`、`points.json`。
- **记下 `scene-config.json` 里的 `anchor.height`**：它是地块的垂直基准，后面接入必须一致。

若该场址要用后端的"通视/视场按地形裁剪"能力，还要把高程场导出一份给后端（独立一步）：

```bash
python tools/terrain_asset/export_heightfield.py \
  --asset work/<场址代号>/build/<资产名>.glb \
  --sources work/<场址代号>/sources \
  --out <后端高程场资源目录>
```

- 导出的是 float32 高程网格，与生成器**逐字对齐**（同一套锚点/尺寸/网格/细节参数），
  否则后端算出的本地坐标会和 GLB 差出几米；
- 导出前脚本会自校验：用 `points.json` + `scene-config.json` 重算每条视线净空并与配置比对，不一致直接报错。

### ④ 合成纹理（中心高清 + 外围低清）

```bash
python tools/terrain_asset/composite_imagery.py \
  --outer work/<场址代号>/outer-z17/stitched.png \
  --center work/<场址代号>/center-z19/stitched.png \
  --outer-width 6000 --outer-depth 4500 \
  --center-width 1000 --center-depth 750 \
  --size 8192x6144 --feather 64 \
  --out work/<场址代号>/composite-8192.jpg
```

- 做了两件事：**色彩匹配**（把中心区三通道均值对齐到外围，避免两家影像色差）+ **边缘羽化**（64 px 高斯过渡）。
- 外圈影像用 `fetch_imagery.py --zoom 17 --width 6000 --depth 4500` 抓一次即可。
- ⚠️ **纹理总量是固定的**：8192 铺 6000 m ⇒ 约 0.73 m/px；铺 3000 m ⇒ 约 0.37 m/px。**外扩范围必然牺牲中心密度**，这是取舍不是 bug。

### ⑤ 换纹理 + 完整性校验（**校验是硬规矩**）

```bash
python tools/terrain_asset/replace_texture.py \
  --glb work/<场址代号>/build/<资产名>.glb \
  --image work/<场址代号>/composite-8192.jpg \
  --out work/<场址代号>/build/<资产名>-hires.glb \
  --size 8192x6144

python tools/terrain_asset/validate_glb.py work/<场址代号>/build/<资产名>-hires.glb
```

- `validate_glb.py` 检查：文件长度字段、JSON/BIN 分块、bufferView 与 accessor 范围、贴图可解码。
- **必须看到"结论：通过"再往下走**。曾经因为长度字段算错产出过坏文件，浏览器表现是"一直转圈不出图"，很难查。

### ⑥ 抓远景层（推荐；解决"转到低角度看到地块边缘"）

```bash
python tools/imagery_fetch/fetch_farfield.py \
  --anchor-lon 113.541523 --anchor-lat 24.4162209 \
  --out frontend/public/farfield
```

- 产物：嵌套金字塔 `{z}/{x}_{y}.jpg` + `manifest.json`（含范围、层级、许可说明）。
- 默认四层（z15/z14/z13/z12，覆盖 9→72 km）+ z0~z11 祖先层补全，共约 300 张、约 4 MB。
- **同一场址只需抓一次**；换场址要重抓（不同场址不能共用）。

### ⑦ 接入与正式化

**预览（不碰数据库，改本地 `.env.local`）**
```dotenv
VITE_ASSET_OVERRIDE=/models/<资产名>/<资产名>-hires.glb
VITE_FARFIELD=local+ion
```
⚠️ **覆盖开关必须限定项目**（见第 4 节坑 5）——否则所有场景都会被同一份资产覆盖。

**正式化（需要 A 侧配合）**
1. 资产放到 `frontend/public/models/<资产名>/`；
2. 用 `emit_scene_migration.py` 出迁移草稿，**开新版本号**（不能改已执行过的迁移）；
3. 更新数据库里的 `asset_url` 与 `asset_sha256`；
4. 前端会做哈希核对——**登记值必须与新资产一致**，否则大屏会按设计报"资产未核对"。

## 3. 每次必过的验收清单

- [ ] `validate_glb.py` 结论为"通过"
- [ ] 大屏加载后左下角诊断行有 `模型半径=xxx(场景实测)`，不是 `?`
- [ ] 测点落点与影像地物偏差可接受（有控制点就做残差校核）
- [ ] 拉到最大缩放、转到接近水平：**看不到地块硬边**（远景层生效）
- [ ] 地块没有悬空/下沉（锚点高度与 DEM 基准一致）
- [ ] 首屏加载时长可接受（>30 MB 的资产先在本机测一遍）
- [ ] `ASSET_PROVENANCE.md` 与实际数据源一致（影像源、许可、是否示意级）

## 4. 已知的坑（都是实战踩过的）

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | 换完纹理直接交付 | **必须跑 `validate_glb.py`**；改纹理/合并资产都算 |
| 2 | 远景瓦片全 404，但页面"看着还行" | Cesium 默认模板是 `{z}/{x}/{y}.jpg`，盘上是 `{z}/{x}_{y}.jpg`，**模板必须与盘上命名一致**；否则一直用兜底图层在渲染 |
| 3 | 高德影像整体平移几百米 | GCJ-02 → WGS-84 迭代反算（`fetch_imagery.py` 内置）；Google/Esri/Bing 是 WGS-84 不用转 |
| 4 | 地块悬空或埋进地里 | 锚点高度要与 DEM 基准一致（清远电厂用的是 `anchor.height = -52`） |
| 5 | **资产覆盖影响所有项目** | `VITE_ASSET_OVERRIDE` 是全局的，必须加项目作用域（如 `VITE_ASSET_OVERRIDE_PROJECT=<projectId>`），否则切到别的场景会"跑到另一个地方" |
| 6 | 切场景后相机错乱、回不到原位 | 场景 `destroy()` 要**摘掉相机 postRender 限制器**并复位模块级状态（半径/锚点），否则旧场景的限制器会一直按住相机 |
| 7 | 相机取景"点了才生效、进去不生效" | Cesium 1.145 没有 `model.readyPromise`，访问会抛异常打断初始化——用 `readyEvent` |
| 8 | 视野一压低就看到"虚空" | 铺远景层（第 ⑥ 步）+ 雾（`density` 与 `visualDensityScalar` 要一起给）+ 相机俯仰/缩放约束 |
| 9 | 大资产提交到**公开**仓库 | Google/高德影像条款禁止再分发；仓库必须是 **private**，或资产不入库 |
| 10 | 抓取中途断流 | 直接重跑同一条命令续抓；一次抓几百张被源站 reset 是常态 |

## 6. 还没做、但值得做的（留给下一次）

- **把这条链包成一条命令**：`make_asset --lon --lat --width --depth`，内部串起 6 步，避免手工传参数出错；
- **双层资产**：大范围低清垫底 + 中心高清覆盖，解决"外扩必降密度"的取舍（目前是单张纹理）；
- **自动对位校核**：有控制点时把残差检查接进流水线，不通过就不许交付；
- **轻量档**：同一场址出"标准 / 轻量"两档资产，弱机演示时切换。
