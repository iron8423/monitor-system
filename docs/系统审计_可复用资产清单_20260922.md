# 阶段 A · 可复用资产清单（2026-09-22）

> 判据只有一条：**"下次还能不能用"**——换了场址、换了人、隔了两个月，它是否仍然是"照做就行"的东西。
> 每条标：位置 / 复用什么 / 复用方式 / 维护成本。

## 一、三维资产生产链（最高复用价值）

| 资产 | 位置 | 复用什么 | 复用方式 | 维护成本 |
|---|---|---|---|---|
| 影像抓取（多源） | `tools/imagery_fetch/fetch_imagery.py` | 高德/Esri/Google/Bing/EOX/天地图六源 + 自动坐标系反算 + 重试与断点续抓 | `--anchor-lon/lat --width --depth --zoom --source` | 低（源站点变更时改 URL） |
| 远景金字塔 | `tools/imagery_fetch/fetch_farfield.py` | 「本地远景层」一次抓取、离线可用，含 z0~z15 祖先层避免 404 | 新场址一条命令 + 前端 `VITE_FARFIELD=local` | 低 |
| 地形资产构建 | `tools/terrain_asset/build_terrain_asset.py` | DEM+影像 → GLB（含 ENU 配准、资产版本、迁移草稿、高程场、场景配置） | `--sources` 指向任意场址的 sources | 中（66 KB，是主力工具） |
| 纹理合成 | `tools/terrain_asset/composite_imagery.py` | 外圈低清 + 中心高清合成（色彩匹配 + 羽化），解决两级影像色差 | 任意两个 `stitched.png` | 低 |
| 贴图替换 | `tools/terrain_asset/replace_texture.py` | 不假设贴图是最后一个 bufferView 的 GLB 换纹理 | 任意 GLB + 任意纹理 | 低 |
| GLB 校验 | `tools/terrain_asset/validate_glb.py` | 长度字段/bufferView/accessor 越界/贴图可解码 | **每次改资产后必跑** | 低 |
| 控制点校核 | `tools/twin_check/check_control_points.py` | 资产与实测控制点的残差、锚点建议 | 有 RTK/全站仪数据时 | 低 |

这套链的复用价值在于：**换场址不需要改代码**，只需要经纬度、尺寸、影像源三样输入。目前已经跑通了"清远边坡 → 清远电厂"两次迁移，是真实可复用的证据。

## 六、本轮沉淀的"三维场景接入规范"（建议固化成文档）

把这两天踩到的坑写成一条可重复的路径，下次（或 A）照做即可：

1. 抓数据：`fetch_imagery`（中心高清）+ `fetch_sources`（DEM）+ `fetch_farfield`（远景金字塔）
2. 建资产：`build_terrain_asset` → `composite_imagery` → `replace_texture` → **`validate_glb`（必跑）**
3. 接入：`VITE_ASSET_OVERRIDE` 预览 → 正式化走**新版本号迁移 + 更新 `asset_sha256`**
4. 相机与远景的六条硬约束：相机留在场址 lookAt 变换内 / 不要每帧 setView / Cesium 1.145 无 `readyPromise` / 远景瓦片模板要与盘上命名一致 / lit 档不能关椭球 / 纹理改动必须校验
5. 合规边界：Google/高德/Bing 影像**仅内部预览、不入库、不随交付物分发**；可交付用 Sentinel-2 或采购授权
