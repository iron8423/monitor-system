## 3. 本轮修掉的三个真 bug（症状 → 根因 → 修法）

### Bug 1：配置加载竞态 —— "分区里 0 点 / 标点跑到别的城市"

- **现象**：分区列表里点数算成 0；测点与雷达停在档案坐标（清远），离相机 8300 km，画面上什么都不剩。
- **根因**：`loadZones()` 以前是"边读边应用"，`applyZones()` 需要场景锚点把 `zones.json` 的本地米
  换算成经纬度；而它在 `createViewer()` 之后立刻被调用，`sceneConfig` 往往还是 null →
  经纬度是 `undefined` → `Cartesian3.fromDegrees(NaN)` 抛
  `DeveloperError: normalized result is not a number` → **整个函数中断，后面两份配置根本不读**。
  （异常发生在分区标签之后，所以标签画出来了、看起来"只有点数不对"。）
- **修法**：三份 JSON 各自独立 try/catch、**全部读完再统一应用**；`zoneLayer.build()` 跳过没有经纬度的分区。

### Bug 2：`pin` 实体没删干净 —— "切个分区再切回来，点就不见了"

- **现象**：点分区 → 点回来，控制台刷 `DeveloperError`，那一批测点整体不同步。
- **根因**：`sync()` 的删除分支只删了立柱与圆点，**漏了 `pin-<id>`**。再切回该分区时
  `drawItem` 用同一个 id 再 `add` → Cesium 抛"An entity with id pin-3 already exists"，
  而异常发生在 watch 里 → 整段 `sync` 中断。
- **修法**：删除分支补 `pin`；`drawItem` 里改成本地 `addEntity()`（先按 id 摘再挂，任何来源的残留都不会打断同步）。

### Bug 3：并发建场景互删 —— "雷达名牌/视场覆盖层整个消失"

- **现象**：模型和测点都在，但雷达名牌、扇面、覆盖层全没了（用户描述成"雷达标签浮在空中/雷达不见了"）。
- **根因**：首屏有两条路径同时建场景（`loadData()` 写 projectId 触发项目 watch + `initViewer()` 自己再调一次），
  两边用**同一个实体 id**，输的那边走到 `if (generation !== sceneLoadGeneration) { scene.destroy() }`
  时，按 id 删掉的是**赢的那一边刚建好的实体**。（实测：两次建场景各建 29 个装饰实体，最后页面上一 个都不剩。）
- **修法**：每个场景实例一套 id 前缀（`dt{n}-...`）；`loadProjectScene` 加"同一项目在建就复用"的去重。

### 附带修掉

- **远景低层级是纯白占位图** + **换场址后瓦片 URL 撞名导致浏览器缓存旧影像**（"周围的场景一直加载不出来"的主要成因，
  和之前"开无痕窗口才正常"是同一类问题）→ 见 §2.2 / §2.3。
- 取景诊断定时器读已销毁模型的 `boundingSphere` 抛错、每秒刷一条红字 → 已包 try。

并把 `console.warn` 临时包一层打印真实调用栈——被 catch 吞掉的异常只打 `message` 时，

**两个环境坑（实测踩过）**：

1. 系统里的 `python` 是 WindowsApps 商店桩，在非交互 shell 里会**静默失败**（exit 1、无任何输出）；
   本机可用的解释器是运行时自带的那一个：
   `C:\Users\ASUS\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe`
   （Pillow 已装，做瓦片/图像检查直接能用）。
2. 沙箱会拦 `Remove-Item -Recurse` 这类递归删除；删单个文件用
   `cmd /c del /q "<绝对路径>"`、删空目录用 `cmd /c rmdir "<绝对路径>"`（路径必须写全，别用通配）。

## 9. 关键概念速查

- **锚点覆盖**（`VITE_ANCHOR_OVERRIDE`）：演示资产与远景层真正的场址；数据库里的项目锚点照旧。
- **远景金字塔**（`public/farfield`）：z6 覆盖 72×54 km，往里逐级嵌套到 z15（9×6.75 km）；
  最外几层是"一个像素几百米"的低清层，靠雾收场。`manifest.json` 是唯一描述文件。
- **分区**（`public/zones.json`）：贴地椭圆 + 浮空标签 + 引线，相机预设 `camera{heading,pitch,rangeM}`；
  点分区 = 平移过去 + 过滤测点。
- **预览摆位**（`public/devices.json`）：雷达落位/朝向、7 个测点的本地米坐标；
  只影响显示（`ScreenView.applyPreviewDevices/applyPreviewPoints`）。
- **贴地**：地面是一个 GLB 资产，不在 `terrainProvider` 里，所以不能用 `CLAMP_TO_GROUND`；
  用 `preview.json` 的 `groundHeightM` + 锚点高度直接算。
- **装饰实体**：雷达名牌/扇面/覆盖层统一以 `dt{n}-` 开头，`createDigitalTwinScene` 按前缀幂等清理。
