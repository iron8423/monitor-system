# 通用监测平台 · 需求文档 v2.0（流程跑通版）

> **本版定位**：在**现有系统基础上增量**，目标只有一个——**把"三维场景 + 监测数据 + 影像"这条流程端到端跑通**，
> 并让后续细化（精度、多期、面状形变、报表）有地方长。
>
> **本版不写分工**：只写"要什么、建成什么样、怎么算跑通"；谁做、何时做由排期决定。
>
> **与 v1.0 的关系**：不是重写。v1.0 的产品定位、两条闭环、里程碑思路继续有效；
> 本版把"三维数字孪生"这条线从"预留"提升为**可验收的一等需求**，并补上前一版缺的非功能与验收判据。

---

## 0. 现有基础（本版复用的，不重做）

| 已有能力 | 复用方式 |
|---|---|
| 档案模型：组织→项目→场景→对象→测点→测项 | 直接复用；本版在其上加"空间成果/标定/绑定" |
| 数据接入：`POST /api/v1/ingest`（X-Ingest-Key）+ message-contract 版本化消息 | **所有新数据源统一走它**，不另起平行库 |
| 测量值与查询：latest/series/summary（含"取最新一行"统一口径） | 直接复用 |
| 规则与告警：阈值/升级/防刷屏/恢复 + 设备离线/质量/延迟 | 直接复用；本版给规则加"作用域"（全局/设备类型/测点） |
| 权限与隔离：JWT + RBAC + 项目成员隔离 + **SSE 按订阅者过滤** | 直接复用（三维页也吃这套隔离） |
| 影像：上传/列表/内容/删除（逻辑删除+审计） | 扩展为"批量 + 元数据 + 三维查看" |
| 审计、备份恢复、验收套件（10 套 / 359 断言） | 直接复用；本版新增需求都要补断言 |
| 前端：Vue3 + Vite + Element Plus + ECharts + CesiumJS + Pinia | 直接复用；新增三维图层与场景装配 |

**原则**：能复用的一律复用；新增只做"现有系统确实没有"的部分（空间成果、标定、绑定、三维渲染、回放）。

## 1. 目标与"跑通"的判据

### 1.1 一句话目标

**把现场的三维真相和现场的实时数据放进同一个时空坐标系**：模型回答"这儿长什么样"，监测数据回答"此刻它动了多少"，两条线在同一场景里叠加、可回放、可追溯。

### 1.2 "跑通"的四条判据（可核查，缺一不可）

| # | 判据 | 验证方式 |
|---|---|---|
| 1 | 给一个三维模型（3D Tiles）与一份雷达结果 CSV，**三维场景里能看到模型、雷达位置与朝向、测点及其形变** | 现场/本机打开页面，逐项对照 |
| 2 | CSV 新增数据 → **页面在一个上报周期内自动更新**（无需刷新） | 在上位机目录追加一行，计时看页面变化 |
| 3 | **可用时间轴回放任意历史批次**，回放期间实时数据不污染画面 | 选一个历史批次，切换回放/返回实时 |
| 4 | **无公网环境可独立运行**（模型、地形、底图、字体、图标全部本地） | 断网后重复判据 1–3 |

> 这四条就是本版验收的主线；其余能力都标 P1/P2，不阻塞"跑通"。

## 2. 术语表（先统一口径，避免各说各话）

| 术语 | 大白话 |
|---|---|
| 场景 | 一个可展示的"现场"：包含哪些模型、哪些测点、默认视角 |
| **空间成果** | 一份三维数据（模型/瓦片/点云/正射/全景），带**坐标系、范围、版本、精度声明** |
| 标定 | 把"雷达的坐标语言"和"模型的坐标语言"对上的参数集（位置+朝向+零偏），**带版本、可回滚** |
| 绑定 | 把雷达每批重新认出的目标（Target3）钉到固定的业务测点（东侧坡面1号点） |
| 主测项 | 三维上"当前按哪个指标上色" |
| 量纲 | 这个指标是什么量（形变/速率/温度/开关量），决定能不能和别的指标比 |
| 值类型 | 一条测量值存什么形态（数值/布尔/文本/JSON） |

## 3. 端到端流程（四条链路）

### 3.1 链路 A：三维场景建立

```
模型/点云/正射（外部产出）
 → 预检查（能独立加载、纹理完整、单位比例正确、无倒置镜像）
 → 登记为「空间成果」（坐标系/范围/版本/精度/体积必填）
 → 标定（控制点或人工对齐）→ 保存标定版本
 → 场景装配（成果 + 地形 + 影像 + 测点）→ 场景清单发布
 → 三维页面加载
```

每步判据：① 模型能单独加载；② 成果元数据缺项拒绝入库；③ 3 个检查点残差 ≤ 约定阈值；④ 场景打开位置正确。

### 3.2 链路 B：数据接入

```
设备（雷达/水位计/摄像头…）→ 适配器（协议解码）
 → 标准消息（message-contract，带测点编码/值/时间/质量）
 → POST /api/v1/ingest（幂等：device+message）
 → 落库（按测项拆行；值类型 + 量纲）→ 可查（latest/series）
```

第一版适配器**至少支持 CSV 只读监听**（上位机继续独立运行，**不占用雷达 TCP 5000**），
并兼容三种写文件方式：追加、整文件覆盖、每批/每天新文件。

### 3.3 链路 C：监测闭环

```
测量值 → 规则评估（阈值/变化量/离线/延迟/质量；作用域 全局→设备类型→测点）
 → 生成告警（同点同测项至多一条；等级升高就地升级）
 → 推送（SSE，按订阅者过滤）→ 处置（确认/研判/派单/处置/解除/误报）→ 审计留痕
```

### 3.4 链路 D：查看与回放

```
实时：SSE 增量 → 三维场景中实体原地更新（不重建场景）
历史：按批次回放（时间轴：播放/暂停/单步/倍速/返回实时）
影像：测点影像/巡检记录在三维与详情页均可查看
```

## 4. 功能需求（P0 = 跑通必需；P1 = 明显影响可用；P2 = 增强）

### 4.1 空间成果管理（P0）

| 项 | 要求 |
|---|---|
| 登记 | 上传/挂载一份成果 → 必填：类型、坐标系、范围（包围盒）、版本、来源、精度声明、体积 |
| 版本 | 同一现场可有多份成果/多期模型；新版本不影响旧版本可查 |
| 校验 | 登记时检查主入口文件、相对路径、纹理缺失、单位比例；不合格不入库 |
| 分发 | 提供成果清单与访问地址；支持本地静态服务（离线） |
| 体量与性能（P0 数字） | 单瓦片 ≤ 2 MB；模型总包 ≤ 2 GB；纹理用压缩格式（KTX2/WebP） |

> 复用：直接长在现有"档案"体系里（场景下属资源），不另建一套存储。

### 4.2 三维场景与渲染（P0）

| 项 | 要求 |
|---|---|
| 加载 | 支持 3D Tiles 1.0/1.1 + glTF 2.0；加载进度、失败提示、重试 |
| 装配 | 场景清单描述：成果引用、地形、底图、默认视角、包含的测点 |
| 图层 | 模型 / 雷达 / 监测点 / 临时目标 / 形变箭头 / 状态色斑 / 调试（坐标轴、控制点、误差线） |
| 交互 | 点选拾取、相机飞向点位、图层开关、模型透明度 |
| 性能（P0 数字） | 首屏 ≤ 10 s（目标机型/局域网）；交互 ≥ 24 fps；实体原地更新不重建 Viewer |
| 离线（P0） | Cesium 静态资源、地形、底图、字体、图标全部本地化；**不依赖 ion Token 作为必需项** |

### 4.3 标定与坐标（P0）

| 项 | 要求 |
|---|---|
| 四个坐标空间 | 雷达扫描平面（角度/距离）↔ 雷达局部直角 ↔ 现场模型坐标 ↔ WGS84/ECEF；**显式保存变换，不散落硬编码** |
| 参数 | 雷达位置（经纬高/模型局部）、Heading/Pitch/Roll、角度零偏、距离偏移 |
| 控制点 | 3~6 个不共线控制点；显示每个点的残差与 RMS |
| 版本与状态机 | 未标定 → 估算 → 已校准 → 已验证；可保存/启用/回滚 |
| **精度分级（P1）** | 有 RTK+控制点：平面 ≤ 0.1 m；仅普通 GPS：≤ 1 m；无坐标：**只做局部对齐，不宣称绝对精度** |
| 诚实性 | 未验证前，界面与文档不得宣称测量级定位精度 |

### 4.4 测点与目标绑定（P0）

- 在三维场景中**人工创建/选择业务测点**（永久编号，位置固定）；
- 把当前批次的目标（TargetN）**人工绑定**到业务测点；系统可给"建议"但**不自动确认**；
- 绑定有有效期与容差（角度/距离）；Target 抖动不移动三维点；
- 解除绑定只结束有效期，**不删历史**；
- 未绑定目标显示为"临时/推算位置"（半透明）。

### 4.5 数据接入与适配（P0/P2）

| 项 | 优先级 | 要求 |
|---|---|---|
| CSV 只读适配 | P0 | 监听目录；增量读取；去 BOM；**字段映射可配置**（不写死列名/列序）；三种写入方式兼容 |
| 容错 | P0 | 半行不解析；文件锁重试不判离线；文件变小/被替换 → 重置游标；服务重启从库恢复游标 |
| 幂等 | P0 | 去重键 = 雷达 + 源目标 + 采集时间 + 来源文件（**+ 内容哈希**，防上位机修正同一行被静默覆盖） |
| 时间补全 | P0 | 文件名日期 + 行内时间 + 现场时区；同时保存采集时间/接收时间/原始文本；**推断的时间要打质量标记** |
| 数据对账（P0） | P0 | 每日核对"文件行数 vs 入库行数"，列出缺失/重复/异常行；CSV 列变化要告警 |
| HTTP 标准接入 | P1 | 设备/边缘网关按 message-contract 直接 POST `/ingest`（长期正路） |
| 原始帧通道 | P2 | 预留只读接入（离线复算/云图用），**不阻塞 MVP**，不抢占上位机端口 |

### 4.6 测量值与指标（P0 基础 / P1 扩展）

- P0：沿用现有 `metric`+`measurement`，支持数值型；测项名称/单位来自档案；
- P1：`measurement` 增加**值类型**（数值/布尔/文本/JSON），支持开关量、状态量、文本型传感器；
- P1：`metric` 增加**量纲类别**（形变/速率/温度/开关量…），用于规则与展示的正确匹配；
- P1（可选）：设备规格/物模型（类型 → 测项模板 + 默认阈值），新增传感器只加数据。

### 4.7 规则与告警（P0 复用 / P1 扩展）

- P0：复用现有规则与告警状态机（阈值、升级、防刷屏、恢复、离线/质量/延迟）；
- P1：规则**作用域**扩展为「全局 → 设备类型 → 测点」，支持模板下发；
- P1：规则类型扩展（变化量/速率/窗口聚合），`windowMinutes` 真正参与判定。

### 4.8 影像与巡检（P0 基础 / P1 扩展）

- P0：复用现有影像上传/列表/看图（含三维浮窗）；
- P1：批量上传、EXIF/航点解析、按设备/成果归类、视频"定时截图"（不做流媒体平台）；
- P1：巡检记录（人工/无人机）与测点关联，形成"现场证据"时间线。

### 4.9 时间轴与回放（P0）

- 按扫描批次回放；切换批次时所有点位同步；
- 回放时**停止把实时事件覆盖到画面**；实时事件继续在后台接收，返回实时后重新拉快照；
- 曲线标记当前回放位置；支持播放/暂停/单步/倍速。

### 4.10 报表与导出（P2）

日/周/月报表、告警统计、形变趋势导出（CSV/PDF）；不阻塞跑通。

## 5. 数据模型（在现有表上的增量）

**新增表（Flyway V9+）**

| 表 | 关键字段 | 说明 |
|---|---|---|
| `space_asset` | id、projectId、sceneId、type(MODEL/POINTCLOUD/ORTHO/PANORAMA)、crs、bounds、version、accuracy、sizeBytes、storageKey、checksum、source、createdAt | 空间成果登记（模型/点云/正射/全景） |
| `calibration` | id、radarId、sceneId、version、status、origin(lon/lat/height)、heading/pitch/roll、azimuthZeroOffset、rangeOffset、residualRmsM、controlPoints(JSON)、createdAt | 标定版本（可启用/回滚） |
| `target_binding` | id、radarId、sourceTargetId、pointId、method、angleTolerance、rangeTolerance、validFrom、validTo、status | 目标 ↔ 业务测点 绑定 |

**现有表扩展**

| 表 | 扩展 | 目的 |
|---|---|---|
| `scene` | 加 center/bounds 已有；加 `defaultView`、`activeAssets`(JSON) | 场景装配 |
| `metric` | 加 `quantity`（量纲类别） | 规则/展示口径 |
| `measurement` | 加 `value_type`（+ `text_value`/`json_value`） | 多形态传感器 |
| `monitor_point` | 已有经纬高/档案层级；如需固定点三维坐标，加 `scene_x/y/z`（可选） | 三维固定点 |

> 迁移原则：现有数据**只加列不回填**（默认值），历史不动；新表从零开始。

## 6. 接口契约（在现有 `/api/v1` 上扩展，不另起平行系统）

**复用（不改）**：`/auth/*`、档案 CRUD、`/ingest/measurements`、`/points/*/latest|series`、`/projects/*/summary`、`/alarms*`、`/alarm-rules*`、`/media*`、`/audit-logs`、`/stream`（SSE，按订阅者过滤）。

**新增（三维子域，建议前缀 `/api/v1/twin`）**

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/scenes`、`/scenes/{id}` | 场景清单与装配 |
| POST/GET | `/space-assets`、`/space-assets/{id}` | 空间成果登记与查询 |
| GET/PUT | `/radars/{id}/calibration` | 读取/保存标定（草稿与正式版本） |
| POST | `/radars/{id}/calibration/activate` | 启用某标定版本 |
| GET/POST/DELETE | `/bindings` | 目标绑定 |
| GET | `/snapshot?sceneId=` | 最新完整快照 |
| GET | `/batches`、`/observations/history` | 批次列表 / 点位历史 |
| GET | `/data-source/status` | 数据源状态与最后数据时间 |
| GET | `/events?sceneId=`（SSE） | 实时事件：snapshot / observation / batch-completed / target-appeared / target-disappeared / data-source-status / calibration-updated / heartbeat |

**约定**：沿用现有信封 `{code,message,data}`；时间 ISO8601 带时区；SSE 事件带 `schemaVersion` 与事件 ID（支持断线续接）。

## 8. 非功能需求

| 类别 | 要求（可测） |
|---|---|
| 性能 | 首屏 ≤ 10 s（目标机型、局域网）；交互 ≥ 24 fps；模型总包 ≤ 2 GB；单瓦片 ≤ 2 MB；历史曲线按视图抽样 |
| 离线 | 全资源本地化；无公网可完成判据 1–3；不依赖 ion Token |
| 可靠性 | 适配服务重启不重复导入历史；SSE 断线自动续接；现场机连续运行 ≥ 2 h 无崩溃 |
| 数据保留 | 原始观测长期保留（按项目定策略）；影像/成果按版本保留；删除为逻辑删除+审计 |
| 安全与合规 | 沿用项目隔离与角色权限；**涉密敏感区域不得使用在线地图/云服务**；模型/影像授权需明确 |
| 可运维 | 日志可定位"模型/CSV/数据库/SSE"四类错误；SQLite/PG 可备份恢复；提供启动/停止/升级与回滚说明 |

## 9. 验收（六类，判据带数字）

| 类别 | 判据 |
|---|---|
| 三维场景 | 模型可加载、纹理完整、相机自动定位、**无公网可打开**、加载失败有提示不白屏、切换场景不泄漏内存 |
| 空间标定 | 雷达位置与朝向可见、控制点残差可查、标定可保存/启用/回滚、刷新后固定点位置不变、**精度按分级阈值验收** |
| 实时数据 | 上位机无需停止/改接；CSV 新行自动读入；重复扫描不产生重复记录；半行/文件锁不崩溃；**CSV→页面 ≤ 一个扫描周期 + 约定延迟**；显示采集时间与接收延迟 |
| 目标展示 | 已绑定点显示业务点号；未绑定点标注"临时/推算"；形变数值与 CSV 一致（含正负号与单位）；目标消失状态正确；**视觉放大有倍数说明** |
| 历史回放 | 可按批次切换、所有点同步、曲线与时间轴一致、回放不被实时覆盖、返回实时恢复快照、重启后历史仍可查 |
| 稳定性与对账 | 连续 2 h 无崩溃；刷新自动恢复；适配器重启不重导；**每日对账（文件行数 vs 入库行数）无未解释差异** |

## 10. 里程碑（不涉及分工）

| 里程碑 | 内容 | 完成标志 |
|---|---|---|
| **M1 流程可见** | 样例模型 + 现有 CSV 回放 + 模拟推送；三维页面 + 雷达 + 测点 + 形变 + 时间轴 | 判据 1、3 通过（**不等外部资料**） |
| **M2 真实数据** | 真实模型 + 标定 + CSV 只读适配 + SSE 实时 + 绑定 | 判据 2 通过；控制点残差有记录 |
| **M3 精度与多期** | 离线部署验收、性能达标、多期模型对比、规则作用域扩展、值类型/量纲 | 判据 4 通过；精度按分级达标 |

**关键路径**：外部资料（模型/坐标/雷达姿态/CSV 规律）到位时间。**M1 不被它阻塞**。

## 12. 风险与降级

| 风险 | 降级方案 |
|---|---|
| 模型打不开/纹理缺失/格式旧 | 离线转换（OSGB→3D Tiles）或先用临时模型联调 |
| 模型无坐标 | 3 个控制点人工配准；或只做局部对齐（标注"非绝对定位"） |
| 雷达姿态不准 | 标定页人工调整 + 已知目标反算；固定点人工放置 |
| Y 距离语义不清 | 先只做人工绑定，暂停自动落点 |
| Target ID 漂移 | 人工绑定 + 邻近匹配，不确定标"待确认" |
| CSV 被锁/被覆盖/换日 | 重试 + 复位游标 + 新文件接续（已在需求内） |
| 现场不能联网 | 全离线部署（模型/地形/底图/字体本地） |
| 模型过大/GPU 弱 | 降低 LOD、压缩纹理、关闭高成本特效 |
| 无连续形变面数据 | 用离散点 + LOS 箭头 + 色斑示意并标注 |

## 13. 本版明确不做

- 多租户 SaaS、计费、组织/客户管理；
- 完整工单/派工/报表中心（P2）；
- AI 地质风险预测、自动裂缝识别；
- 自研摄影测量算法、飞控；
- 用离散点生成并宣称"真实测量的连续形变面"；
- 自动改变山体网格几何（只做可视化表达，不伪造几何）；
- 用 TvT.js/TresJS 重写三维前端；
- **占用雷达 TCP 5000 与上位机竞争连接**。
