## 版本约定

- **主文档**只保留一份有效的 `v1.0`；后续若改动，按“v1.1、v1.2…”递增，旧版进 `归档\`，不在主目录留存多个有效版本。
- **历史稿一律放 `归档\`**，只读，不删（留追溯），但不再作为开发依据。
- 新增设计类文档（接口 / 数据库 / 原型 / 测试方案）放 `需求文档\` 或对应子目录，并在本 README 挂索引。
- **2026-09-10 说明**：早期草稿《雷达标准消息契约_v1》已被 `docs/message-contract.md`（M0 冻结版）取代——两者在**测点编码**（草稿 `HUICHU-01/SLOPE-01` vs 冻结 `P-HK01…P-BP04`）与**幂等键**（草稿四元组 `deviceId+messageId+sequence+collectTime` vs 冻结 `device_id+message_id`）上直接冲突。为避免误用，草稿已从仓库移除（追溯见 commit `c1dc169`）；**唯一事实源为 `docs/message-contract.md`**。
- **2026-09-10 说明（二）· 签字流程取消**：项目使用**单仓库（monorepo）单一事实源**——双方读同一份文档、同一份代码，git 历史本身就是「谁在何时同意了什么」。因此**「两人签字」这道流程取消**（它的全部价值是「在没有共享事实源时留一条双方同意的记录」），M0 的收口方式改为**仓库文档与代码保持一致**。
  - **现行事实源**：`docs/message-contract.md`（消息契约）+ `docs/B侧接口契约_M0.md`（接口/字段/枚举）。
  - `docs/M0_接口冻结_致B_v1.md`：**停止作为开发依据**，但**保留在 `docs/` 不归档**——因为 **D1–D10 的编号定义只在这一份文件**，`message-contract.md`（「D2/D3/D7/D8」）与 `B侧接口契约_M0.md`（「见 §4-D6」）都在引用；整体移走会让引用悬空。处理方式是**就地作废**：文首加作废横幅，D5/D6/D2 三处与现状不符的行就地标注「以现行文档/代码为准」。

## 当前开发基线要点（速查）

- 产品：给客户用的通用监测管理系统；首批数据源=毫米波点形变雷达。
- V1 页面：管理后台 + **3D 数字孪生态势驾驶舱（必须，效果对齐参考样图）** + 位移监测分析页。
- V1 闭环：雷达接入 → 3D 标点 → 实时/历史曲线 → 超限告警 → 确认/研判/处置/解除留痕。
- 无人机影像挂点；报警联动加密采集先留接口；界面向华测对齐；初版本地运行。
- 详细需求、边界、优先级、待确认项见 `通用多传感监测管理系统_需求分析与开发指引_v1.0.md`。
