## 1. 这次解决什么

此前 V2 的双雷达大屏用的是一份**纯程序化生成**的山体（`mountain-demo-2.0.0`）：
几何自洽、确定性可复现，但地形本身与任何真实地点无关。用户提出的目标是：

> 「图中的地形，通过卫星图片还原出来；雷达及其数据暂时使用模拟的。」

于是本轮把默认项目的地形换成了**真实地形演示资产**：几何骨架来自公开 DEM，
色彩底来自公开卫星影像，中高频细节为程序化补充（并在来源说明里逐条写明），
雷达位姿、标定与实时数值仍然全部是模拟数据。

「先做离线的」这条要求落实为：运行期不请求任何在线服务（无 Cesium ion、无在线底图、
无在线 DEM），资产是仓库内的一个 GLB，断网可用。

## 7. 已知边界与下一步

1. **不是测绘成果**：30m DEM + 10m 影像 + 程序化细节只解决「像不像」，
   不解决「准不准」。不得用于工程测量、风险评估或应急决策——这条同时写在
   `ASSET_PROVENANCE.md` 与工具 README 里。
2. **接无人机航测时要关掉程序化细节**：`--detail-amplitude 0`，并把测点坐标
   按航测成果重算；管线、迁移与前端都不用改。
3. **视场图形仍未按地形裁剪、也没有自动通视计算**（完善清单第 36/37 条）：
   本轮只把「标定关系」的视线算准了（逐米步进），雷达扇面在屏幕上仍是解析扇形。
4. **影像分辨率是硬上限**：若现场要求 0.5m 级观感，唯一的合法路径是采购影像或
   用无人机航测正射影像替换本流水线的影像输入。
5. **资产版本与标定的关联仍未做**（完善清单第 38 条）：V18 只把资产版本写进
   `digital_twin_scene`，`device_point` 还没有 `asset_version` 外键。

## 8. V2 迭代：场景放大、雷达外移、修掉「雷达悬空」

### 8.1 用户报的问题与根因

现象：大屏上两台雷达与视场扇面**浮在半空**，测点却贴在坡面上。

根因是生成器的一处**单位口径 bug**：`build_radars()` 把雷达位姿的
`localPosition[2]` 写成了**绝对高程**（基准面 + 本地相对高度），而生成迁移草稿时
又加了一次基准面（`altitude = floor + localPosition[2]`），于是
`device.altitude = 2 × 107 + 相对高度`——整整高出场景 107m。ENU 本地坐标里
`+Z` 的零点就是基准面，这里只能写相对高度。修法：

- `localPosition[2]` 回归**相对高度**（与 GLB 网格同一套坐标）；
- 绝对高程另存 `absoluteAltitude`，只给 SQL/文档用；
- 迁移 `V19` 重写了 `device.altitude`（131.001 / 71.275），并保留其余标定值。

顺带修掉一个同源问题：解算雷达朝向时用的是**圆均值**，目标跨 0° 时会被密集一侧
拉偏（南侧雷达三个目标实际只占 52.1° 弧，圆均值算出 0.9°，使最远目标偏差 32.8°，
被误判为超出 ±30° 视场）。现在改用「最小覆盖弧的中点」。

## 9. 关于「用更多卫星地图与高程数据」

本轮把**覆盖范围**扩大了（更多瓦片），但分辨率受两个免费源的硬上限约束：

| 数据 | 免费可离线的上限 | 本资产实际使用 | 想再进一步需要什么 |
|---|---|---|---|
| 高程 | 30m（SRTM / Copernicus GLO-30 / ALOS AW3D30） | 30m 级（Mapzen/AWS terrarium） | 5m 级 DEM：商业采购，或无人机航测 DSM |
| 影像 | 10m（Sentinel-2，CC BY 4.0） | 10m（EOX cloudless 2023） | 0.3–0.6m：商业影像授权，或现场航拍/无人机正射 |

Google / Esri 的高分辨率瓦片**不能离线缓存或再分发**（条款禁止），内网部署要用必须买授权；
Google 中国区影像还带 GCJ-02 偏移，与 WGS-84 测点叠加会整体错位。
因此「更精细」的正当路径只有两条：采购授权影像，或等现场无人机航测成果——
后者接入本流水线时只需 `--detail-amplitude 0`，其余代码不用改。

### 9.1 公开 DEM 到底有没有 5m 的

直接回答：**在中国境内，免费公开的 DEM 基本只有 30m 一档，没有 5m**。现成的免费选项：

| 数据集 | 分辨率 | 覆盖 | 许可 |
|---|---|---|---|
| SRTM（本资产所用 Mapzen/AWS 瓦片的来源） | 1 弧秒 ≈ 30m | 全球 60°N–56°S | 公有领域 |
| ASTER GDEM v3 | 30m | 全球 | 免费，署名 |
| ALOS AW3D30 | 30m | 全球 | 免费，署名（AW3D 5m/0.5m 是商业产品） |
| Copernicus DEM GLO-30 | 30m | 全球 | 免费（GLO-10 是商业的 WorldDEM） |
| NASADEM / FABDEM | 30m | 全球 | 免费 |
| TanDEM-X 90m | 90m | 全球 | 免费（12m 商业） |
| USGS 3DEP | 1–10m | **仅美国** | 公有领域 |
| 英国 EA LiDAR / 荷兰 AHN / 瑞士 ALTI3D | 0.5–2m | 仅本国 | 各国开放数据 |

也就是说，**5m 级 DEM 只有三条路**：① 商业采购（AW3D 5m、WorldDEM、国内的高分/资源三号
测绘产品）；② 无人机/机载航测（本项目后续计划的正是这条）；③ 少数地区的政府开放数据
（中国不在其列）。

**本资产当前用的是 30m 级 SRTM 派生数据**（terrarium 瓦片，z=15 ≈ 4.4m/px 的过采样，
底层信息量仍是 30m）。影像同理：免费可离线的是 Sentinel-2 的 10m，0.5m 级只能用商业
影像或航拍正射。

## 10. 后端通视校核用的高程场（2026-09-20，复查清单 P1-10）

**为什么还要单独导一份**：后端只装自己那个 jar，拿不到 2GB 级的 DEM 瓦片，也跑不动 Python。
在此之前，`device_point.line_of_sight` 就是**生成器写进迁移的一个布尔**——平台对"这条视线
现在到底还成不成立"没有任何复核能力。所以把生成器解算出的**最终高程场**原样导出，让后端
用同一套口径自己算。

```
python3 tools/terrain_asset/export_heightfield.py \
    --asset frontend/public/models/qingyuan-hillside-v2 --sources generated/terrain-asset/sources-v2 \
```

产物（`backend/src/main/resources/terrain/`）：

| 文件 | 内容 | 体积 |
|---|---|---|
| `<资产版本>.bin` | 相对基准面的高度网格，`float32` 小端、行主序（i 沿 x 最快） | 山地 185KB / 桥梁 76KB / 铁路 170KB / 工厂 119KB |
| `<资产版本>.json` | 锚点、基准面 `floor`、宽深、网格尺寸、`mPerLon/mPerLat`、细节幅度与种子、网格 SHA-256、自校验结果 | 每份 1KB 以内 |

**导出前必须自校验**：脚本用资产目录里的 `points.json` + `scene-config.json` 重算每条视线净空，
与 `scene-config` 里记的值比对；偏差超过 0.01m 就**拒绝导出**。这一步挡的是"用错的 DEM 素材
或错的网格参数重建出一片很像、但不是同一片的地形"——那会让后端给出一个看着有道理的错误答案。
当前四个场景 25 条视线全部复现，最大偏差 0.0008m（float32 存储舍入）。

**口径必须逐字对齐生成器**（改了这里就要改 `build_terrain_asset.py`，反之亦然）：

1. 本地坐标 +X 东、+Y 北、+Z 上，原点在锚点；`xs = linspace(-W/2, W/2, cellsX+1)`；
2. `grid[j][i]` 是相对基准面的高度，绝对高程 = `floor + sample(x,y)`；
3. 经纬度 ↔ 本地米用**锚点处**的 `mPerLon/mPerLat` 常数（不是逐点重算）；
4. 双线性采样把索引夹到 `[0, cells - 0.001]`；
5. 视线逐米步进：`steps = max(8, int(水平距离))`，取样点 `t = step/steps`、`step = 1..steps-1`，
   判据 `最小净空 > 0.25m`。

Java 侧对应 `com.monitor.twin`（`TerrainHeightfield` / `LineOfSight` / `TerrainHeightfieldService` /
`TerrainSightService`），对齐由 `TerrainSightRegressionTest` 用**迁移里抄下来的 24 条视线**钉住。

**接入航测数据时**：同一条路——`export_heightfield.py` 只是把生成器的输出落成网格，
换成 5cm 级 DSM 时，把 `--sources` 指到航测成果、重建资产、再导一次即可；
`detailAmplitude` 应为 0（航测几何不需要程序化细节）。届时后端不需要任何改动。
