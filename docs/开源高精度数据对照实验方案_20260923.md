# 开源高精度数据对照实验方案（数据等级 → 效果与精度验证）

> 目的：**在零采购成本的前提下，用公开高精度数据回答"数据到位后我们能做成什么样"**，
> 为《数字孪生总体方案》里的资源决策提供实证依据。
> 版本：2026-09-23　｜　执行：B（前端/三维）　｜　预计工期：半天~1 天

---

## 0. 为什么要做这个实验

现状是"技术已到位、卡在数据"。老板要判断"值不值得买影像/做航测"，靠说没用，靠图有用：

**同一块地，用三档数据各做一份资产，同机位截图并排**——观感差多少、能看清什么、体积多大，一眼可见。

这个实验的另一个好处：**完全不依赖甲方的图纸和授权**，我们自己就能完成，属于"没有资源也能往前推"的工作。

**交付物**：
1. 三档资产（GLB）× 3；
2. **同机位对照图 1 张**（这是给老板看的那张）；
3. 数据表：每档的 GSD、网格、面数、体积、首屏加载时间；
4. 一页结论：数据等级 ↔ 可判读性 ↔ 成本量级的对应关系。

## 1. 实验设计（控制变量）

| 变量 | 设定 |
|---|---|
| 场址 | **同一块**（见第 2 节），中心经纬度与范围完全一致 |
| 场景尺寸 | 统一 2000×1500 m（三档相同，保证可比） |
| 网格密度 | 4 m（三档相同——**只变数据，不变参数**，这样差异一定来自数据） |
| 纹理尺寸 | 统一 4096×3072（三档相同） |
| 相机 | 同机位、同朝向、同俯角（用同一份场景配置） |

**三档数据**：

| 档位 | 高程 | 影像 | 类比成本 | 预期表现 |
|---|---|---|---|---|
| **T1 现状档** | SRTM 30 m（现用） | Sentinel-2 10 m（现用） | 0 元 | 糊、只有宏观起伏，看不出结构物 |
| **T2 中度档** | SWISSALTI3D **0.5 m** | swisstopo 正射 **0.1 m** | 采购影像/低空航测，几千~几万元 | 道路、建筑、坝体轮廓清楚，地形真实 |
| **T3 高精档** | 同 T2（或 swissSURFACE3D 点云） | 同 T2 + 真实立体外观 | 航测/激光扫描，万元级 | 近景也能站住，有真实立面 |

## 2. 试验场址：瑞士 Grande Dixence 大坝周边（推荐）

**坐标**：约 7.404° E, 46.081° N（瓦莱州，大坝与库区）

**为什么选它**：
- 场景构成与我们高度相似：**库区 + 坝体 + 山区边坡**，正好对应灰库/坝体/边坡监测；
- 地形起伏大（大坝高 285 m），能体现高精度 DEM 的价值；
- 有明确的人造结构体（坝体、道路、缆车、水电站），能检验"结构物看得清不清"；
- 数据源**已实测可从国内直连**（见第 3 节）。

**备选场址**：荷兰（PDOK 航拍 + AHN 0.5 m LiDAR，地势平坦、适合检验城市/构筑物）；国内场址暂不适用（高精度测绘成果受管制，天地图需授权）。

## 4. 技术路线（三档怎么产出）

### T1 现状档（零改动）

```bash
python tools/terrain_asset/fetch_sources.py --anchor-lon 7.404 --anchor-lat 46.081 --width 2000 --depth 1500 --out work/dixence/t1/sources
python tools/terrain_asset/build_terrain_asset.py --scene mountain --sources work/dixence/t1/sources \
  --width 2000 --depth 1500 --cells-x 500 --cells-y 375 --texture-width 4096 --texture-height 3072 \
  --asset-name dixence-t1 --out work/dixence/t1/build
```

### T2 中度档（需要一步数据转换——本实验的主要技术工作）

**影像**：给 `fetch_imagery.py` 增加一个 `swisstopo` 源（URL 模板已确认），WMTS 是标准 `{z}/{x}/{y}`，改动很小：
```
--source swisstopo --anchor-lon 7.404 --anchor-lat 46.081 --width 2000 --depth 1500 --zoom 17
```
（z17 时 0.1 m 原始影像约为 0.75 m/px；要更高就抓 z18/z19，体积相应增大。）

**高程**：SWISSALTI3D 是 **GeoTIFF（EPSG:2056, CH1903+/LV95）**，与我们流水线现用的 terrarium PNG 瓦片格式不同，需要一个转换步骤：

**方案 A（推荐，改动小）**：新增脚本 `tools/terrain_asset/geotiff_to_terrarium.py`
- 输入：GeoTIFF（可多个，覆盖目标范围）
- 处理：重投影到 EPSG:3857 → 重采样到目标缩放级别 → 编码为 terrarium PNG（`h = R*256 + G + B/256 - 32768`）→ 输出 `dem/<z>/<x>_<y>.png` + manifest
- 输出：与我们现有 `sources/` 目录格式一致 → **后面完全复用现有流程**

**方案 B（改动大，不推荐）**：让 `build_terrain_asset.py` 直接读 GeoTIFF（需要引入 rasterio 与重投影逻辑）。

**然后**：`build_terrain_asset` → `composite_imagery` → `replace_texture` → `validate_glb`（与现有链路一致）。

### T3 高精档（可选，验证"真三维外观"）

两条路，任选其一：
- **3D Tiles 样例验证**（最快）：用 `CesiumGS/3d-tiles-samples` 里的倾斜摄影样例，直接在大屏加载，验证"实景三维能接进来"；
- **点云验证**：取 swissSURFACE3D 的小范围点云 → 网格化（ODM/Open3D）→ 出资产。工作量较大，可作为第二阶段。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 坐标系：瑞士用 CH1903+/LV95（EPSG:2056），与 WGS-84 不同 | 转换脚本里做重投影；影像走 WMTS 的 3857 版本，天然是 Web Mercator |
| 数据量大：0.1 m 影像 + 0.5 m DEM 覆盖 2000×1500 m 很大 | 控制范围与层级；先出 2000×1500 一档，够用即可 |
| 许可署名 | swisstopo 为开放数据，需在 `ASSET_PROVENANCE.md` 与界面上保留署名 |
| 网络中断 | 抓取工具已支持重试 + 续抓；源站限流时拆范围分批抓 |
| 时间成本 | 若 DEM 转换卡住，先只做"影像升级"的 T1/T2 对照——**影像才是观感差异最大的那一档** |

## 8. 这个实验的结论怎么用

1. 进《数字孪生总体方案》作为"数据等级 ↔ 效果"的实证章节；
2. 给老板做资源决策：**花几千元买 0.5 m 影像 ≈ 从 T1 到 T2 的那一步**，图上直接可见；
3. 给甲方要图纸/控制点时，用它说明"影像能解决'看得清'，但解决不了'尺寸准'——尺寸只能靠图纸或测量"。
