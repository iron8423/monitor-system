# 3D 数字孪生 V2：双雷达标定、升级与验收

## 1. 本次解决的问题

旧演示把 7 个测点都绑定到山体一端的一台雷达。页面能显示数据，但没有证明目标位于量程和视场内，
也没有检查山体遮挡，因此不能代表真实布站关系。

V2 将数据关系升级为“雷达目标标定”：

- 北侧 `radar-001` 负责 `P-HK02`、`P-HK03`、`P-BP01`、`P-BP02`；
- 南侧 `radar-002` 负责 `P-HK01`、`P-BP03`、`P-BP04`；
- 每条关系记录目标号、绝对方位角、俯仰角、斜距、反射器高度、LOS、地形最小净空和有效期；
- 新绑定默认为 `PENDING`，不能在生产严格模式中接收测值；
- 标定只有通过雷达量程、水平视场和垂直视场校验后才能成为 `ACTIVE`；
- ingest 在 `INGEST_STRICT_CONTRACT=true` 时只接受当前有效的 `ACTIVE + LOS` 关系。

演示地形的 LOS 来自同一个确定性地形函数的沿线采样。真实项目仍须用现场 DEM/点云、全站仪/GNSS
测得的设备和目标坐标重新计算，并完成人工通视复核。

## 3. 管理端标定流程

先建雷达和测点，再绑定：

```http
POST /api/v1/devices/{deviceId}/points/{pointId}
Authorization: Bearer <ADMIN_OR_MAINTAINER_TOKEN>
```

此时状态为 `PENDING`。提交现场计算结果：

```http
PUT /api/v1/devices/{deviceId}/points/{pointId}/calibration
Authorization: Bearer <ADMIN_OR_MAINTAINER_TOKEN>
Content-Type: application/json

{
  "targetCode": "RADAR-A-TARGET-007",
  "azimuthDegrees": 252.734,
  "elevationDegrees": 9.546,
  "slantRangeM": 157.160,
  "reflectorHeightM": 2.5,
  "lineOfSight": true,
  "minimumClearanceM": 2.695,
  "validFrom": "2026-09-16T00:00:00",
  "validTo": null,
  "note": "现场坐标复测与 DEM 视线校验通过"
}
```

后端会拒绝超量程、超水平/垂直视场、LOS 为 false 或有效期倒置的结果。现场设备移动、基准重置、
目标重装或地形/植被显著变化后，必须重新标定，不能继续沿用旧关系。

## 4. 前端核对

进入 `/screen` 后：

1. 右侧雷达列表应有两台设备；
2. 点击雷达，只显示该雷达到其标定目标的 LOS；
3. 点击测点，浮窗应显示来源雷达、目标号、斜距、LOS 和标定状态；
4. 北侧、南侧目标数量分别为 4 和 3；
5. 启动双雷达模拟器后，7 个点都应出现累计形变和形变速率。

```bash
python3 tools/radar_simulator/radar_simulator.py --dry-run --once
python3 tools/radar_simulator/radar_simulator.py --count 10 --interval 1
```

若页面显示“暂无数据”，先检查 ingest 响应中的 `reason`。`DEVICE_POINT_NOT_BOUND` 表示设备归属错，
`DEVICE_POINT_NOT_CALIBRATED` 表示关系仍是 PENDING、LOS 未通过或已过期。

## 5. SQL 验证

字段在本项目中叫 `point_code` 和 `measure_value`，不是 `measurement_point_code` 与 `value`：

```sql
SELECT device_id, point_code, metric_code, measure_value, unit, collect_time
FROM measurement
ORDER BY collect_time DESC, id DESC
LIMIT 20;
```

核对标定关系：

```sql
SELECT d.code AS radar, p.code AS point, dp.target_code,
       dp.azimuth_degrees, dp.elevation_degrees, dp.slant_range_m,
       dp.line_of_sight, dp.minimum_clearance_m, dp.calibration_status
FROM device_point dp
JOIN device d ON d.id = dp.device_id
JOIN monitor_point p ON p.id = dp.point_id
ORDER BY d.code, dp.target_code;
```

演示库应得到 7 行且全部为 `line_of_sight=true`、`calibration_status=ACTIVE`。

## 7. 能否直接投入生产

代码包现在具备生产接入所需的数据闸门和可追溯标定结构，可用于现场联调和试运行；模拟数据不能把
模拟山体升级为测绘成果。正式投产前仍必须完成：真实模型/DEM 配准、每台雷达和每个目标现场标定、
厂商协议转换器、24 小时稳定性测试、备份恢复演练、HTTPS/来源限制，以及报警阈值的业务签字。

换言之，后续替换真实资产和真实档案时无需重写 3D、实时数据和告警主链路，但不能直接沿用本包中的
模拟坐标、LOS 结果或设备参数作为工程结论。
